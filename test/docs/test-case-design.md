# Ballance 比赛控制台测试用例设计

`apps/server/src/referee-controls.test.ts` 覆盖保分直达下一关 Ready（不发送一分钟提醒）、暂停时 T-60 提前/延后与开始后拒绝、时限缩短越界双层关窗、连接故障时矩阵及旧确认提交拒绝；直接切关还需在 SQLite 关闭重开后保持目标与旧成绩。

时限修订回归：`apps/server/src/runtime-deadline.test.ts` 验证工作运行 60 秒延至 120 秒后写入、关闭、重建服务并接收第 70 秒完赛；同时验证测试模式向前/向后改期同步计分窗口。

## Go 后通知与恢复回归（2026-09-12）

- Go 后 0ms/999ms 无可派发的已起跑 Bulletin，1000ms 可派发一次；重复 Go 和迟到倒数不重复通知，也不推迟尝试计时。
- 一秒等待期间触发保护作废尝试，旧通知取消；测试时钟与工作时钟共用同一最早发送边界。
- 保存、关闭并重建 SQLite 服务，延迟通知的最早发送时间与 Go 一同重定位，未写入命令审计的通知仍 pending；到期后不受自动化暂停阻断，但真实发送仍要求连接认证正常。`READY!` 仍随发令流程暂停，覆盖 SR 单行和 HS 两行（第二行“记得收分”），以及快照恢复后继续 cheat off、双行协议编码与回显确认。
- `manual-only-audit.test.ts` 从未启用自动化的运行开始，逐关手动 Ready、cheat off、Go、接收成绩、提前结束，验证所有关卡完成并归档；跨关手动倒数绑定计划目标。
- 真实 MockClient 管道测试启动本地服务器时保持 stdin 打开，避免 EOF 被服务端当作 stop；实服自制图探针采用独立合成 MD5，不复用官图示例哈希。

工具链、Windows 进程清理、测试实例隔离和浏览器等待约定见[开发与验证指南](../../docs/development-guide.md)。本文件维护行为用例与验收结果，不重复平台操作步骤。

所有时间用例使用可控单调时钟和固定墙上时间。所有文件用例在临时目录运行；源夹具读取前后保存大小、最后写入时间和 SHA-256。写动作统一生成比赛 ID、期望状态版本和幂等键；需要确认的用例另生成与目标、影响和版本绑定的短时令牌。

### 3.2 实服协议门禁

- `npm run test:live-probes` 是显式联网、写命令的双服务器门禁，固定串行覆盖 `1.bmmo.win`、`2.bmmo.win`；`npm run test:live-work` 是同一门禁的兼容别名。
- 执行前必须同时设置 `BALLANCE_ALLOW_LIVE_COMMANDS=1` 与独立恢复授权 `BALLANCE_ALLOW_LIVE_RECOVERY=1`，并由每台服务器的首条 `list` 证明普通玩家为 0、取得本机 `*ContestConsole` 当前连接 ID；未经裁判明确批准不得覆盖占用保护。
- 两台服务器分别输出 `test/artifacts/live-work-mode-<server>.json`，汇总输出 `live-work-mode-summary.json`；产物记录 MockClient 版本、连接 ID、命令结果和回显形态差异，但不纳入版本控制。
- 单服定向补跑或产物中的 `recovery.status=not-requested` 只证明该次实际覆盖的服务器和协议分支，不得计为正式双服恢复门禁、20 秒冷却复验或现场验收；同名 artifact 会被后续运行覆盖，历史结论必须另存不可覆盖证据或内容哈希。
- 恢复探针逐服核对精确自 Kick/1101、软重连新 ID、同名拒绝/1002、受管进程强制关闭后的身份释放和新进程认证；两服最大身份释放时间不得超过固定 20 秒冷却。
- 任一服务器占用、身份未知、权限失败、回显不匹配、身份释放超过 20 秒或未执行，都表示本阶段现场门禁未通过；一台服务器的成功不能替代另一台。
- 该门禁验证协议和目标账号，不替代带真实参赛者、成绩接收、恢复与归档的完整现场彩排。

## 10. 准入、准出与证据

## 11. 待澄清项

以下问题不阻塞目录和用例设计，但在对应自动化断言落地前必须确认：
