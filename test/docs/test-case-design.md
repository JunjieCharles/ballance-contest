## 1. 设计依据与目标

本文覆盖以下基线：

- [后端需求](../../docs/contest-console-backend-requirements.md)
- [前端需求](../../docs/contest-console-frontend-requirements.md)

- [成绩表视觉样例](../../docs/scoreboard.xlsx)
- [MockClient 本地说明](../../server-windows/README.md)

目标是验证配置、工作/测试模式控制、身份、状态机、事故、计分、修订、导出、归档、恢复和本地安全的完整闭环。主观违规、录像真实性、代打和申诉结论只验证“进入人工复核并保留证据”，不设计成系统自动裁决。

## 2. 测试分层与执行约定

| 层级 | 目录 | 主要替身/环境 | 失败定位 |
| --- | --- | --- | --- |
| 单元 | `unit/backend/` | 内存时钟、构造日志行、纯领域对象 | 解析、计分、状态迁移规则 |
| 后端组件 | `component/backend/` | 临时 SQLite、假进程、内存 WebSocket | 进程、存储、API、命令回显 |
| 前端组件 | `component/frontend/` | 浏览器 DOM、Mock HTTP/WS、固定快照 | 页面、表单、交互、可访问性 |
| 集成 | `integration/` | 真 SQLite + 假 MockClient + 浏览器 | 跨模块事务与同步 |
| 端到端 | `e2e/` | Windows 本机服务、浏览器、可控服务器 | 裁判业务旅程 |
| 非功能 | `non-functional/` | 压测事件源、场景故障、长时运行 | 时延、可靠性、安全、兼容性 |

优先级：P0 是发令、成绩、恢复和安全阻断；P1 是核心管理与可用性；P2 是诊断、兼容性和扩展边界。除明确标注人工检查的 `RULE-*` 外，均以自动化为目标。

所有时间用例使用可控单调时钟和固定墙上时间。所有文件用例在临时目录运行；源夹具读取前后保存大小、最后写入时间和 SHA-256。写动作统一生成比赛 ID、期望状态版本和幂等键；需要确认的用例另生成与目标、影响和版本绑定的短时令牌。

## 10. 准入、准出与证据

准入条件：需求版本固定；MockClient 适配版本明确；数据库迁移可初始化；前后端契约可用；测试时钟、假进程和临时目录可注入；综合夹具哈希匹配。

发布准出条件：全部 P0 通过；P1 无影响发令、成绩、恢复或安全的未解决缺陷；三轮主场景和单目标场景确定性通过；工作/测试隔离与源日志只读校验通过；30×30×8h 长时测试无丢失/重复；Edge/Chrome 与受支持 Windows 冒烟通过；归档哈希可复算。历史参考日志不作为发布门禁。

每次失败至少保留用例 ID、应用/适配器/解析器版本、配置版本、比赛/轮次/尝试、状态版本、事件序号、假时钟时间、原始事件引用、命令审计和脱敏诊断。不得把会话令牌、完整 UUID 或非必要聊天写入测试报告。

## 11. 待澄清项

以下问题不阻塞目录和用例设计，但在对应自动化断言落地前必须确认：

1. 已解决：有效完赛后再次上报同关 DNF 时保留首次有效完赛，后续 DNF 仅作异常留档；通过独立最小场景验证。
2. 综合日志含多次重复 Get ready。清单记录了“下一关首次观察到的 Get ready”，但成绩接收窗口的权威关闭点应来自状态机事务，不能只凭日志文本反推；完整逐事件黄金清单需结合人工确认的现场状态补齐。
3. `scoreboard.xlsx` 的选手显示名与综合日志不同，当前仅作为视觉/复制格式样例，不作为该日志的最终计分黄金数据。
