## 命令行参数

BallanceMMOServer 支持通过命令行参数进行启动配置。常用参数如下：

### 启动参数列表

| 短参数 | 长参数 | 说明 | 默认值 |
| ------ | ------ | ---- | ------ |
| `-p`   | `--port=PORT` | 指定服务器端口 | `26676` |
| `-l`   | `--log=PATH`  | 指定日志文件路径（输出到文件，同时输出到控制台） | 空（仅控制台） |
| `-h`   | `--help`      | 显示帮助信息并退出 | - |
| `-v`   | `--version`   | 显示版本信息并退出 | - |
|        | `--dry-run`   | 仅测试服务器启动，立即退出（不实际运行） | - |

#### 示例

```shell
./BallanceMMOServer --port=26676 --log=server.log
./BallanceMMOServer -p 26676 -l server.log
./BallanceMMOServer --help
```

#### 参数详解

- `-p PORT`, **`--port=PORT`**  
  指定服务器监听端口，默认是 `26676`。  
  示例：`--port=12345`。
- `-l PATH`, **`--log=PATH`**  
  日志文件保存路径，支持绝对或相对路径。将所有日志同时写入文件和控制台。  
  示例：`--log=./server.log`。  
  注意：如果未指定日志路径，则日志仅输出到控制台；此外，可以使用 `start_ballancemmo_loop.sh` 脚本来自动启动服务器并将日志输出到以日期命名的文件中。
- **`--dry-run`**  
  测试服务器启动流程，仅初始化后退出，不实际运行服务。  
  用于配置或调试环境。
- `-h`, **`--help`**  
  显示完整参数帮助列表并退出，不会启动服务器。
- `-v`, **`--version`**  
  显示服务器版本、构建时间、最低支持客户端版本等信息并退出。

## 配置文件参数

BallanceMMOServer 的配置文件为 `config.yml`，位于服务器根目录下。该文件使用 YAML 格式，包含了服务器的各种半永久性配置选项。

### 总体格式说明

- 配置文件内包含了服务器上次读取时的版本和时间，以及简单注释说明。
- 每个配置项均可留空，服务器会补充默认值。
- 修改配置后请重启服务器或在控制台执行 `reload` 命令以重新加载配置。
- 配置文件损坏时服务器会生成默认配置并打印提示。

### 简单配置项

| 配置项 | 类型 | 默认值 | 说明 |
| ------ | ---- | ------ | ---- |
| enable_op_privileges | bool | true | 是否启用管理员（OP）权限系统。OP 可执行特殊操作。若不启用则视作所有玩家均有权限。 |
| restart_level_after_countdown | bool | true | 在倒计时“Go!”后是否强制所有玩家重启关卡，否则只会重置得分和生命数。 |
| force_restart_after_countdown | bool | false | 是否无条件强制所有玩家在“Go!”后重启关卡（正常情况下仅同一关卡玩家会受影响）。 |
| save_player_status_to_file | bool | false | 是否将玩家登录状态写入到 `player_status.json` 文件（可以接外部工具实时读取在线玩家量和时长）。 |
| log_installed_mods | bool | false | 是否在玩家进入服务器时记录其安装的 MOD 信息到日志文件。 |
| log_ball_offs | bool | false | 是否记录玩家掉球事件到日志文件。 |
| serious_warning_as_dnf | bool | false | 玩家收到严重警告（非法重开、使用自杀器）时，是否将其自动标记为未完成（DNF）状态。 |
| ghost_mode | bool | false | 是否启用幽灵模式：玩家之间不可见，仅旁观者和 OP 可见其他玩家。 |
| logging_level | string | "important" | 日志输出详细等级。支持：important、warning、msg。 |
| auto_flush_log | bool | false | 是否每次日志输出后立即刷新到文件（适用于需要外部工具实时读取分析日志时）。 |

### 其他复杂配置项

- `map_name_list`
  * 类型：字典（map），格式为 `md5_hash: 地图名称`。
  * 说明：用于给地图指定服务器和玩家视角下的名称，便于识别与展示：
    + 服务器内广播的地图名称由玩家进入地图时自动提交，名称采取先到先得机制。
    + 例如，两名玩家 P1 和 P2 先后进入同一自制地图，但两人对该地图的命名分别为 `M1` 和 `M2`，由于 P1 先进入此地图，两人视角下地图名字均为 `M1`。本配置相当于让服务器预先占据上对应的地图名称——若服务器设置该地图名称为 `M0`，则无论两玩家怎样设置自己本地地图名，服务器内均会显示 `M0`。
    + 值得注意的是，由于玩家客户端的地图名称来自于文件名，若两玩家进入命名相同的不同地图，则仅仅根据地图名无法判断两人是否处于同一地图。同样由于文件名的性质，其无法包含特殊字符（如 `/` 等），因此服务器可以预设使用特殊字符的地图名，保证比赛时玩家均进入设定好的同一地图。
  * 示例：
    ```yaml
    map_name_list:
      "d41d8cd98f00b204e9800998ecf8427e": "超级关卡/比赛地图"
      "e2fc714c4727ee9395f324cd2e7f331f": "第二关"
    ```
- `initial_life_counts`
  * 类型：字典（map），格式为 `md5_hash: 初始生命数`。
  * 说明：配置每个关卡的初始生命数量。默认无预设时为 3，预设数值超过 3 时玩家进入关卡会直接补充至该数量的生命。
  * 示例：
    ```yaml
    initial_life_counts:
      "d41d8cd98f00b204e9800998ecf8427e": 3
      "e2fc714c4727ee9395f324cd2e7f331f": 5
    ```
- `forced_names`
  * 类型：字典（map），格式为 `UUID: 强制昵称`。
  * 说明：为指定 UUID 的玩家强制设置昵称，登录时会自动更改。由于本功能在服务器判定名称合法性后才会生效，因此可以用于强制设置带有非法字符的昵称等。
  * 示例：
    ```yaml
    forced_names:
      "00000001-0002-0003-0004-000000000005": "示例玩家"
    ```
- `reserved_names`
  * 类型：字典（map），格式为 `昵称: UUID`。
  * 说明：某昵称只允许特定 UUID 使用，其他玩家（非该 UUID）尝试以此昵称登录时会被拒绝加入。可以用于保护特定昵称不被其他玩家占用。
  * 示例：
    ```yaml
    reserved_names:
      "示例玩家": "00000001-0002-0003-0004-000000000005"
    ```
- `forced_cheat_modes`
  * 类型：字典（map），格式为 `UUID: bool`。
  * 说明：强制指定 UUID 的玩家为作弊模式（`true`）或非作弊模式（`false`），无法自行调节。
  * 示例：
    ```yaml
    forced_cheat_modes:
      "00000001-0002-0003-0004-000000000005": false
    ```
- `op_list`
  * 类型：字典（map），格式为 `昵称: UUID`。
  * 说明：管理员（OP）列表。玩家以设置中的昵称登录时会获得 OP 权限。OP 可以执行特殊操作，如踢出玩家、修改配置等。
  * 示例：
    ```yaml
    op_list:
      "示例玩家": "00000001-0002-0003-0004-000000000005"
    ```
- `ban_list`
  * 类型：字典（map），格式为 `UUID: 封禁原因`。
  * 说明：被封禁玩家（UUID）及其封禁原因。被封禁后无法进入服务器。
  * 示例：
    ```yaml
    ban_list:
      "00000001-0002-0003-0004-000000000005": "违反规则，被封禁"
    ```
- `mute_list`
  * 类型：列表（array），每项为 UUID 字符串。
  * 说明：被禁言玩家列表（UUID）。被禁言后无法发送聊天信息。
  * 示例：
    ```yaml
    mute_list:
      - "00000001-0002-0003-0004-000000000005"
      - "abcd0001-1234-5678-abcd-000000abcdef"
    ```

## 内部命令

下文命令的描述格式和注意事项：

- 不同参数之间以空格分隔；未使用任何格式的参数表示玩家必须原样输入参数名称。
- `<参数>` 表示必须根据实际状态输入的参数。
- `[参数]` 表示可以省略（将会使用默认值）的玩家参数。
- `参数1|参数2` 表示玩家需要选择参数 1 或参数 2 中的一个填入。
- `{玩家}` 表示玩家名称或前缀了 # 的玩家内部临时 ID（可以用 `list` 获取）。
  * 例：若一玩家名为 Player，ID 为 1145141919，则可以输入 `Player` 或者 `#1145141919`。
  * 服务器玩家名支持模糊匹配，若有多个玩家名以相同前缀开头，则会提示冲突并要求更精确输入。例如，服务器内有玩家 `Player012` 和 `Player123`，则输入 `Player` 会提示冲突，但输入 `Player0` 则会匹配到 `Player012`。
- `{玩家+}` 表示支持多个玩家名称或 ID，至少需要一个，多个玩家间以 `,`（不含空格）分隔。
  * 例：`Player1,Player2,#1145141919`。
- `{关卡}` 表示关卡名称或哈希值（可以用 `listmap` 获取），其有两种输入方式：
  * 原版关卡直接输入 `level 关卡号`，如 `level 12`。
  * 输入哈希值**及关卡号**（关卡号在此没有任何意义，但客户端仍需要接收），如 `1234567890abcdef1234567890abcdef 12`。哈希值可以通过 `listmap` 获取。
- 命令参数的完整名称以及玩家名或玩家 ID 可以输入首字母后在输入框内按下 Tab 键自动补全，方便快速输入。
- 固定的命令和玩家名不区分字母大小写，但玩家根据实际状态自行填入的其他参数区分。此外，Tab 键自动补全时由于补全库自身设定问题，也区分大小写。
- 控制台会对错误用法给出提示或警告。
- 部分命令支持 YAML 或特殊格式输入（如 `playsound`, `playstream`, `popup`）。

### 核心服务器管理

- `stop [重连延迟]` – 停止服务器。可选参数为重连延迟（正整数，单位为秒，不小于 0 或大于等于 50），可以让玩家在服务器关闭后等待重连延迟秒后自动重连。
- `reload` – 从 `config.yml` 重新加载服务器配置，重新加载失败时会显示错误。
- `flushlog` – 刷新日志文件。正常情况下不需要手动执行；服务器日志一般是先被写入内存缓冲区，定时或在特定事件后才写入磁盘，但有时（尤其是如果接了读取分析日志的外部插件时）需要手动刷新。
- `version` 或 `ver` – 显示服务器版本信息、最低客户端版本和运行时间。

### 玩家管理

- `list`  
  列出所有在线客户端（玩家和旁观者）。
- `list-uuid`  
  列出所有在线客户端及其 UUID。
- `ban {玩家} [原因]`  
  封禁玩家。可以通过连接 ID 或名称封禁，并附带原因。
- `unban <uuid>`  
  通过 UUID 字符串解除玩家封禁。由于玩家名称可以随意更改，封禁是通过 UUID 实现的，封禁后玩家无法再进入服务器，因此需要提供玩家的 UUID。
- `listban`  
  显示封禁列表。
- `op {玩家}`  
  赋予玩家管理员权限。
- `deop {玩家}`  
  移除玩家管理员权限。
- `mute {玩家}`  
  禁言玩家。
- `unmute {玩家}`  
  解除玩家禁言。
- `listmute`  
  显示禁言列表。

### 通讯命令

- `say <内容>`  
  向所有玩家发送聊天消息。
- `whisper {玩家+} <内容>`  
  向指定玩家发送私聊消息。
- `plaintext <内容>`  
  向所有玩家发送纯文本消息（玩家收到的信息将不带有任何额外信息，例如发信人来源等；适用于服务器的一些特殊功能插件）。
- `plaintext# {玩家+} <内容>`  
  向指定玩家发送纯文本消息。
- `popup <内容>`  
  向所有玩家发送弹窗消息。内容的格式为 `标题: 内容`（遵守 YAML 单条配置的标准格式），例如 `popup 你好: 我是弹窗文本`。标题可以省略，直接使用 `popup 我是弹窗文本` 发送纯文本弹窗消息。
- `popup# {玩家+} <内容>`  
  向指定玩家发送弹窗消息，格式同上。
- `announce <内容>`  
  向所有玩家发送重要通知（公告）。使用 `\n` 可以换行，用 `\\n` 可以在内容中包含 `\n` 字符。
- `announce# {玩家+} <内容>`  
  向指定玩家发送重要通知（公告）。
- `notice <内容>`  
  向所有玩家发送提示通知，格式同上。
- `notice# {玩家+} <内容>`  
  向指定玩家发送提示通知。
- `bulletin [内容]`  
  设置服务器公告（持久性通知），格式同上。内容留空等同于清除公告。客户端会在连接时自动获取当前公告内容；一般而言，客户端支持最多显示 3 行公告。公告会在服务器空载时（所有玩家均退出后）被自动清除。
- `getbulletin`  
  获取当前服务器公告内容（因为直接用 `bulletin` 命令会清除公告，所以需要用 `getbulletin` 获取当前公告内容）。

### 玩家与地图查询

- `getmap`  
  显示每位玩家当前地图和小节。
- `getpos`  
  显示每位玩家当前位置和球的类型。
- `listmap`  
  列出服务器内缓存的所有地图名称及其哈希值。地图缓存会在服务器空载时（所有玩家均退出后）被自动清除。

### 管理操作

- `kick {玩家} [原因]`  
  踢出玩家。可以通过连接 ID 或名称踢出，并附带原因。
- `crash {玩家} [原因]`  
  使玩家客户端崩溃，通常用于测试或强制断开。
- `fatalerror {玩家} [原因]`  
  触发玩家客户端致命错误。其他客户端会看见玩家被踢出，原因是 `fatal error`。客户端除了断线识别码外无法判断是否是服务器故意触发的。
- `kick# <代码> {玩家} [原因]`  
  使用指定代码踢出玩家，并附带原因。**注意**：不同于其他命令，此处的后缀 `#` 表示使用特定的断线识别码。断线识别码是一个整数，通常用于标识特定的断线原因。若识别码在 1150 至 1199 之间，则客户端会在等待 `识别码 - 1150` 秒后自动重连（可以用于使客户端快速重连刷新服务器设置）。

### 关卡与倒计时操作

- `countdown {玩家} {关卡} [模式] [类型]`  
  服务器以指定玩家身份启动关卡倒计时（服务器**无法直接**发令，必须以指定在线玩家身份）。控制台会提示可用参数和类型（模式默认为 `sr`；类型 `4` 和 `5` 分别为预备和提醒预备，`0` 为起跑；不输入类型时服务器会自动倒数 3 秒后起跑）。  
  示例: `countdown Player level 12 sr 0`——以 Player 的身份发令，SR 模式起跑第 12 关。
- `countdown-forced [hs]`  
  向所有玩家广播强制倒计时并重开关卡。不建议使用，因为会导致所有玩家的游戏状态被重置。`hs` 参数表示是否使用 `hs` 模式（默认为 `sr` 模式）。
- `restartlevel {玩家+}`  
  请求玩家当前关卡重开。

### 音效与流操作

- `playsound <标题>: [[频率, 时长], ...]`  
  向所有玩家广播音效，支持复杂参数格式或 YAML 配置。标题可选，不写标题时玩家侧不会有任何提示。频率和时长单位为毫秒（ms）。例如：`playsound 音效标题: [[440, 1000], [880, 500]]`。
- `playstream <路径>`  
  向所有玩家广播音效。音效文件必须要为 WAV 格式，且不大于 512 KB。参数可以为路径或 YAML 格式详细定义时长、音高等（直接输入 `playstream` 可以查看提示）。
- `playstream# {玩家+} <路径>`  
  向指定玩家发送音效。

### 分数查询

- `scores [hs|sr] [{关卡}]`  
  查看最近游玩地图或指定地图的分数列表。
- `sendscores [hs|sr] [{关卡}]`  
  向所有玩家广播分数列表。
- `sendscores# {玩家+} [hs|sr] [{关卡}]`  
  向指定玩家发送分数列表。

### 全局作弊管理

- `cheat on|off`  
  切换全局作弊状态。

### 帮助

- `help`  
  打印所有可用命令的帮助信息。
