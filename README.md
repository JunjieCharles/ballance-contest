# Ballance 比赛控制台

Ballance 比赛控制台是一套在 Windows 本机运行的裁判工具，用于托管 BallanceMMO MockClient、控制比赛流程、处理事故与重赛、实时查看和修订成绩，并导出或归档比赛数据。

当前版本：`0.1.0-dev`

> 当前版本适合测试演练、目标服务器彩排和受控的小型赛事试运行。工作模式已经接通真实 MockClient，但正式使用前仍应完成目标服务器的账号、网络和完整流程彩排。具体状态见[开发进展](docs/development-progress.md)。

## 主要功能

- **工作模式**：托管真实 MockClient，读取比赛日志，串行发送命令并记录回显。
- **测试模式**：从玩家行为场景创建测试运行；普通、高手、低手和捣乱玩家会响应裁判状态，比赛流程仍由裁判系统推进。
- **裁判控制**：Bulletin、Notice、Announce、公共聊天 `s`、Ready、倒计时、手动 Go、Ready/关卡时限改期、延时、结束轮次、重赛本关、手动标记当前关已起跑、强制重置本关、强制进入下一关、Kick 和原始命令。
- **实时成绩**：完赛、DNF、违规排除、人工修订和运行期计分映射调整后生成新的榜单版本，页面实时刷新名次与得分。
- **复制与导出归档**：复制可直接粘贴到 Excel 或腾讯在线表格的富文本/TSV 表格，下载 XLSX、CSV，并生成带版本与哈希记录的比赛归档。
- **本地持久化**：比赛、配置、运行快照、命令审计、榜单和归档记录保存在 SQLite 中。
- **操作保护**：每个需要确认的按钮都会在旁边用简短文案说明点击后会发生什么；内部目标串、哈希、状态版本和令牌不占用裁判确认内容。断开实时连接时禁止写操作；其他浏览器标签页默认只读。
- **原始日志**：工作和测试模式都有独立的右下角 Client 日志悬浮窗，默认展开，可拖拽、缩放、刷新或最小化；只有更新前已经在底部时才自动跟随新行。

## 快速开始

### 运行 Windows 便携包

便携包自带 Node.js 和运行依赖，使用电脑无需预装开发环境。

1. 打开 `dist/portable/BallanceContestConsole`。
2. 双击 `Start-ContestConsole.cmd`。
3. 保持启动窗口运行，浏览器会自动打开控制台。
4. 新建比赛默认为工作模式；首次演练请主动切换为测试模式。

控制台地址形如：

```text
http://127.0.0.1:38623/#token=...
```

启动器会自动关闭上一个由本项目启动的控制台实例并释放 `38623`。如果端口由其他程序占用，启动器会显示进程信息并停止启动，不会误杀无关程序。

### 数据保存位置

默认数据目录：

```text
%LOCALAPPDATA%\BallanceContestConsole
```

其中包含 SQLite 数据库、日志、导出和归档。正式比赛前建议备份此目录；比赛运行期间不要手工修改其中的文件。

## 第一次使用

### 1. 新建比赛

在左侧“比赛”区域填写名称并选择模式：

| 模式 | 用途 | 是否连接真实服务器 |
| --- | --- | --- |
| 工作模式（默认） | 真实比赛和目标服务器彩排 | 是 |
| 测试模式（备选） | 裁判培训、流程演练、计分验证、故障演练 | 否 |

模式在比赛创建后不可互换。测试数据会带有明显标识，避免与正式比赛产物混淆。

两种模式使用同一套比赛配置、状态机、真实时间节奏、计分、榜单、修订、导出和归档。测试模式只把真实玩家输入与 MockClient 命令传输替换为确定性的测试玩家和安全模拟适配器。

### 2. 配置并发布

打开“比赛配置”页：

1. 填写比赛名称和服务器。服务器控制身份固定为 `ContestConsole`，MockClient 始终以 `*ContestConsole` 旁观登录。
2. 在“小型赛事预设”“大型赛事预设”中选择计分预设，点击后会出现确认面板；确认后整体覆盖当前计分。之后仍可直接修改每个名次，但手工改动需点击“保存计分规则并覆盖单关配置”才会落盘并同步到全部关卡。小型赛事为前 12 名 `20,15,12,10,8,6,5,4,3,2,1,1`，第 13 名起为 0 分。
3. 使用 `SR1–13`、`HS1–13` 预设整体替换关卡草稿，之后仍可继续直接编辑每关。配置写入期间整块配置区会短暂锁定，必须等新快照落地后才接受下一次预设或保存，避免连续操作把旧版本误提交为 409。模式可选“官图 SR / 官图 HS / 自制图 SR / 自制图 HS”：官图只设置关卡号并显示为 `SR1`、`HS1`，自制图填写用于通知和榜单的名称以及完整 32 位 MD5，发令时自动使用隐藏关卡号 `0`。每关支持增删、复制，并通过最左侧三横杠手柄排序；拖动时完整卡片跟随指针，目标位置显示等高占位。拖动后仍需点击“保存关卡列表”，未保存修改会在发布检查中被拦截。
4. 如有需要，在“玩家”页设置“游戏内玩家 ID → 排行榜显示名”映射。
5. 点击“发布比赛”；参赛者无需提前登记。

发布会执行字段校验并保存不可变规则快照。参赛者将在工作模式中根据上下线和 MockClient `list` 自动登记，显示名映射可以在发布后继续维护。

当前前端已提供逐关配置、单关计分编辑和“是否启用起跑保护”（默认开启）；其余流程策略和通知模板仍使用已发布配置中的默认值，尚无完整可视化编辑器。如正式赛事需要改动这些默认值，应先在彩排中确认方案，参见[开发进展中的 P0 项](docs/development-progress.md#p0正式赛事前)。

## 测试模式操作

测试模式不需要粘贴 JSON，普通使用流程如下：

1. 新建测试模式比赛，配置并发布；玩家由行为场景提供，轮次与计分沿用当前比赛配置。
2. 打开“测试”页选择场景。小型综合沙盒为 20 人（8 普通、6 高手、3 低手、3 捣乱者），大型综合沙盒为 30 人（12 普通、8 高手、6 低手、4 捣乱者）；另有保护期崩溃、服务器断线、MockClient 退出和时钟跳变等专门故障场景。
3. 查看玩家行为后点击“创建测试运行”。场景不会包含 Ready、Go 或换轮脚本。
4. 切换到“控制台”启动自动化。首次启动会先公布关卡和准备时间，并按轮间等待预留默认 3 分钟；测试页不提供第二个自动化开关。两种模式都按 1× 真实时间运行相同的固定 Ready/cheat/倒数边界、轮间等待和关卡时限。
5. 每个场景带固定随机种子：同一场景可重复得到相同的玩家完成时间、分数和异常选择，但不同玩家不会整齐地执行固定动作。低手可能提前 DNF，也可能一直等待到关卡超时。
6. `+15 秒`、`+3 分钟` 是裁判主动选择的快进工具，只用于缩短演练；不点击时始终按真实时间推进。
7. 故障由所选场景按阶段相对触发；综合沙盒只包含少量短暂掉线，Warning、DNF 和 cheat 属于玩家行为而不是故障，不提供临时手动故障按钮。
8. 在“控制台”查看流程动态、处理阻断、事故和重赛；需要裁判判定 DNF 时，到“成绩”页修改该关成绩。

测试运行会把状态机、计分引擎、虚拟时钟、参与者连接/cheat 状态和故障进度作为一个一致快照保存。裁判执行 Ready/Go、改期、延期、提前结束、重赛、手动标记起跑、强制重置或强制进入下一关后，即使关闭并重新启动服务，也会恢复动作后的关卡、尝试来源、榜单和 T-60 边界；恢复后自动化先保持暂停。

旧的逐事件日志材料仅由自动化测试和后端回放接口使用，不在裁判界面提供 JSON 导入，也不能代替裁判系统发令。

工作比赛不显示“测试”标签或测试运行按钮；测试场景、虚拟时钟和快进控制只在测试比赛中出现。

测试模式中的命令只记录为模拟结果，不会联网、启动真实 MockClient 或发送真实服务器命令。Kick 和原始命令等真实副作用操作会禁用，相关异常通过故障场景演练。

## 工作模式操作

### 赛前准备

确认便携包的 `server-windows/` 中存在以下文件：

- `BallanceMMOMockClient.exe`
- `GameNetworkingSockets.dll`
- `libcrypto-3-x64.dll`
- `libprotobuf.dll`
- `yaml-cpp.dll`

在目标服务器上先确认：

- 裁判账号有发送 Bulletin、Notice、Announce、公共聊天 `s`、Ready、倒计时、Go 和 Kick 等所需权限。
- 服务器地址和网络可达。
- 服务器已为固定身份 `*ContestConsole` 配置比赛控制权限，且现场没有另一个同名控制客户端。
- 日志目录可写且磁盘空间充足。

### 启动比赛

1. 新建工作模式比赛，完成规则配置后直接发布，无需预登记参赛者。
2. 打开“控制台”，点击“连接比赛服务器”。
3. 在“命令审计”中确认连接和命令回显。仅出现 `Connected to server OK` 不代表连接已经可用：系统还会等待登录拒绝观察窗口结束，再主动执行一次完整 `list`，只有该批名单唯一确认固定身份 `*ContestConsole` 的新连接 ID 后才进入健康状态。健康连接再次出现 `Connected` 会重新认证；已经红色阻断的连接不会因此自行启动恢复。
   若已发布配置含自制图，MockClient 每个新进程在上述认证成功后会按关卡顺序一次性发送 `setmap <完整MD5> 0 <地图名>`。同一进程中的注册一旦中断不会自动重发；自动流程会转为硬重启，只有新进程重新认证后才重新尝试注册，权限失败则直接红色阻断而不循环。
4. 点击“启动自动化”可按默认 3 分钟准备时间规划首轮；点击“进入 Ready+发令流程”会把目标关第一条 Ready 改为 1 分钟后，立即发送 Bulletin 和赛前 Notice，并自动推进后续发令。
5. 观察顶部阶段、当前轮次、“本关 Ready”“本关起跑/预计起跑”“本关最晚结束”和“下一关 Ready”的 UTC+8 时间。Ready 两栏都表示对应关的第一条 Ready；首关只规划本关时，下一关显示“未设置”。建立有效尝试后，起跑栏显示实际 `goAt`，而不是继续显示估算值。

下一关第一条 Ready 前 60 秒是明确的关卡边界。到达该时刻时，控制台会原子地把当前关切换为下一关、关闭上一关成绩窗口，并允许在成绩页修订上一关；这一切换不等待第一条 Ready 真正发出，即使自动化处于暂停或一般阻断也会按既定计划发生。迟到的上一关完赛、DNF、Warning 和带 `[CHEAT]` 的完赛仍保留在原始日志中，但不再进入成绩、排除或注意事项。

控制台认证完成后会在大厅、暂停或复核等安全阶段每 30 秒执行一次 `list` 对账，不会插入 Ready/Go 等关键流程。系统只在该 `list` 命令真正进入等待回显状态、紧邻写入 stdin 前打开本批收集窗口；旧式列表头或实服“客户端行 + 末尾玩家/旁观者汇总”必须完整且数量一致才会一次性更新参与者状态。不完整或汇总不符的批次不会写入半份名单，并会冻结后续发令、启动一次完整自动恢复；恢复后下一次定期 `list` 仍无有效回显时报告红色阻断并开放人工恢复。普通玩家也会在 login、disconnect 事件中自动登记，名称以 `*` 开头的旁观者不会进入参赛者列表。

托管进程的 stdout/stderr 会持续排空，控制台只在内存中保留最近 64 KiB 诊断尾部，避免长赛程输出填满管道后让 MockClient 假死。每条命令从入队时开始计算覆盖排队、stdin 写入和回显等待的总超时；在写入前已经耗尽期限的积压命令会标记为“已取消”，以后也不会补写。graceful stop 同样从操作开始计总超时，迟到回调不会改写已经终结的状态。

发令回显同时核对固定身份与本机 MockClient 当前连接 ID；该 ID 必须先从本次连接的 `list` 结果确认，尚未确认或重连后旧 ID 都不能确认命令。普通玩家发出的同地图 Ready、3/2/1 或 Go 只进入原始日志，不会确认裁判命令或改变比赛阶段。官图名称兼容 `Level 01` 与注册后的 `Level_01`；HS 的官图名称、官图哈希和带引号自制图回显都会带 `<HS>`，Ready、倒数、Go 与完赛按该标记归属；DNF 协议不带模式标记，按当前安全地图上下文归属。全局关闭 cheat 只认本机 `toggled cheat off globally!` 回显，不会被玩家自行关闭 cheat 的日志误确认。

连接卡会显示 `正在连接 → 正在认证 → 健康 → 可疑 → 恢复中 → 已阻断` 六种状态，以及进程代次、连接代次、当前裁判连接 ID、恢复步骤和最近服务端证据。`Login denied`、1002 和 2000 都是认证失败；处于健康状态前，除认证与恢复通道外的普通真实命令不会发送。

### 玩家 ID 与排行榜显示名

- 玩家 ID 是游戏内名称，例如 `Silent_Snow`，不是日志里的 `#123456` 数字连接 ID。
- 数字连接 ID 仅作为本次连接和重连历史记录。
- 默认排行榜直接显示玩家 ID。
- 可在“玩家”页设置 `Silent_Snow → 渴望新地图`；映射只改变排行榜和导出显示，不改变成绩归属与计分。
- 黑白名单和改名冲突控制属于后续功能。

Ready、cheat off、Go、Kick、原始命令或地图注册等会改变现场状态的真实命令失败/结果不确定时会暂停未来发令，但已开放成绩窗口、关卡时限和可用的定期 `list` 仍继续。正常恢复时，结果不确定的命令逐条选择“确认已执行”或“执行重发”；明确失败的命令逐条选择“确认不再执行”或“执行重发”。确认不会发送，重发会创建新的命令审计并等待新回显，原 `failed/uncertain` 记录永久保留，处置结论在服务重启后仍有效。若现场已经无法可靠逐条恢复，可经“重赛本关”确认把这些未决记录从新 Ready 周期的阻断中隔离；这不会把原命令改写成已执行。普通 Bulletin/Notice/Announcement/公共聊天以及手动 `list`、`listmap`、`scores` 等只读命令的失败或超时只显示黄色注意事项，不单独阻断；定期在线名单 `list` 无服务器回显按连接可疑处理，执行一次完整两级恢复后仍无回显才阻断。

命令审计不会把 `> command` 本地 stdin 回显、其他玩家日志或无关的 `success/disconnect` 当成服务器确认。通知和发令按协议精确核对本机身份；公共聊天 `s` 只认当前连接 ID、固定 `*ContestConsole` 和完整文本一致的聊天回显。Kick 只认目标玩家断开，本机探针退出只认包含原原因的 `1101: Kicked by *ContestConsole (...)`；高级原始命令若没有可安全识别的成功回显会保持“结果不确定”，必须由裁判按该条命令确认或重发。

若服务器反馈 `Action failed: you don't have the permission to run this action.`，系统会把命令标为失败并阻断自动化，明确提示修复 `ContestConsole` 权限。服务重启时会先使用已持久化的权威 Go 和尝试证据核对 `sent` 命令，已经证明确实执行的命令不会误报为结果不确定。

MockClient 进程意外退出，或日志出现 `Disconnected from server.`、`The host hath bidden us farewell.  (5003: Connection dropped)` 等连接事故时，会立即冻结后续自动发令，但已开放的成绩窗口和关卡时限仍继续。工作模式只执行一套自动恢复：先通过专用生命周期通道软 `reconnect`；软重连中新 `Connected` 前出现的预期断开只作为换代边界，仍须用新 ID 的完整认证证明成功；未能重新认证时对旧 MockClient 执行有界 graceful stop；仍不退出时按受管子进程句柄、PID、可执行路径和完整命令行精确核验所有权，核验通过才强制结束进程树；确认退出后固定冷却 20 秒，再启动一个新进程并重新认证。任何步骤失败都会转为红色阻断，不形成恢复循环，也不会按进程名或端口猜测并结束其他程序。

健康连接上的“软重新连接”会先以固定原因精确自 Kick 本机 `*ContestConsole`，只有收到原因匹配的 1101 服务端回显后，才把 `reconnect` 作为断线后的唯一下一条生命周期命令；已有明确断线证据的自动恢复不会重复自 Kick。该动作仍需绑定服务器、受管 PID 和双 generation 的高风险确认。

每次连接切换都会增加 generation。只要 stdin 已经尝试写入，Ready、关闭 cheat、Go、Kick、地图注册和原始命令等高风险命令即使写回调随后失败也转为“结果不确定”；尚未写入的旧代流程动作或已经耗尽自身排队期限的命令保持“已取消”。旧代迟到回显和地图注册协程不能确认命令或改变新代状态。新进程通过身份认证后还会完成一次地图注册；注册完成前，现场动作、自动化派发和“执行重发”继续冻结，但不影响裁判本地选择“确认已执行/确认不再执行”。连接恢复后自动化仍保持暂停，由裁判点击“恢复自动化”继续，或使用相应的现场恢复动作。

工作模式在健康连接时分别提供“软重新连接”和“重启 MockClient”：前者只请求服务器重连，后者执行受管进程停止、冷却、重启和重新认证。两者都属于高风险确认，确认内容绑定当前服务器、受管 PID、进程 generation 和连接 generation；目标发生变化后旧确认失效。同一动作和规范化输入使用相同幂等键的并发请求会合并到同一次操作，不会重复 reconnect、停止或启动进程；把同一幂等键复用于不同动作或输入会被 409 拒绝。测试模式使用“模拟恢复连接”。

控制台服务整体重启后，“恢复比赛现场”会恢复原阶段、尝试、榜单、截止时间、计划，以及最近连接状态、进程/连接 generation 和服务端证据，不会建立新比赛或清空成绩；真实连接仍须重新通过完整认证。Ready、倒计时、比赛中或尾部接收阶段的中断会形成红色“服务中断观察缺口”，因为期间可能漏掉 Go、完赛、DNF、Warning、cheat 或掉线；裁判可逐条选择“确认带缺口继续”，之后再恢复自动化，也可用“重赛本关”一次隔离全部开放缺口并立即从当前关 Ready 重新开始。两种操作都保留原证据、不补造事件。

## 裁判控制台

### 流程操作

| 操作 | 作用 | 注意事项 |
| --- | --- | --- |
| 发送通知/公共聊天 | 通过 Bulletin、Notice、Announce 或 `s` 向比赛服务器发送裁判文本 | 发送前检查目标比赛、类型和文本；`s` 不允许换行 |
| 进入 Ready+发令流程 | 规划并自动发令 | 立即预告，1 分钟后按 `Ready×3 → READY! → cheat off → 3/2/1/Go` 自动推进 |
| 手动 Ready | 单次发送 Ready | 不改变阶段、计划时间、Bulletin 或自动流程进度 |
| 关闭 cheat | 单次发送关闭命令 | 不改变计划；成功回显作为目标关手动发令前置证据 |
| 手动发令 | 人工介入起跑 | 不要求 Ready 序列或等待计划时间；目标关 cheat off 已确认且无权限/连接/未决命令阻断时立即倒数，仍开启 cheat 的玩家在权威 Go 时排除；只有权威 Go 后更新发令与最晚结束时间；始终使用仅影响同地图玩家的普通 Go |
| Ready 延后 1 分钟 | 顺延已安排的 Ready | 仅赛前等待、轮间、尾部接收或重赛准备阶段可用 |
| 本关时限延长 1 分钟 | 顺延当前关卡最晚结束时间 | 仅比赛中或成绩接收窗口开放时可用 |
| Ready 改期 / 关卡时限改期 | 共用 UTC+8 时间输入，分别修改两类计划 | 两个按钮互不改变另一类时间 |
| 提前结束本轮 | 结束当前轮次 | 保留本关原最晚结束时间，只重新规划并 Bulletin 通知下一 Ready |
| 重赛本关 | 强制隔离当前流程阻断并立即把当前关复位到 Ready | 活动运行中始终可用；已有尝试会作废，尚未 Go 时不补造尝试；原始证据和审计永久保留，只有新 Go 创建新尝试 |
| 手动标记当前关已起跑 | 在系统未识别到外部人工发令时建立当前关有效尝试 | 仅当前 Ready 且尚无有效尝试时可用；从确认成功执行时刻计算 `goAt` 和本关时限，不发送服务器命令、不回放外部 Go 时间、不补记标记前结果；自动化保持暂停 |
| 强制重置本关（T-60） | 清除本关有效尝试和成绩，从本关准备边界重新开始 | 活动运行中始终可用；旧尝试、榜单版本、事件和审计保留，第一条 Ready 安排在动作后 60 秒 |
| 强制进入下一关 | 保留本关成绩并立即跨越下一关 T-60 边界 | 非末关且比赛未结束/归档时可用；动作时立即关窗、切换当前关并开放旧关修订，下一关第一条 Ready 安排在 60 秒后 |
| 起跑保护已使用/未使用 | 手动切换本关保护消耗状态 | 使用结构化确认并随运行恢复；比赛配置未启用起跑保护时保留按钮但禁用 |

发布前不会开放裁判操作按钮（通知、Ready、手动 Go、改期、时限控制、四个强制关卡恢复入口、Kick、原始命令和结束比赛均禁用），仅保留删除比赛入口用于中止草稿流程。

关卡动作的实际目标统一由后端计算。尾部成绩接收及从该状态暂停时，Ready 流程、单次 Ready、关闭 cheat 和手动发令都指向已规划的下一关；强制进入下一关指向后端返回的下一关，其他强制恢复动作指向后端返回的当前关。确认面板只展示后端返回的标签、目标和影响，不再用页面上的旧 `currentStageId` 猜测。确认同时绑定目标关、runtime 版本及相关计划/尝试影响，任一项变化后提交旧确认会收到 409，并要求按最新快照重新确认。若是从比赛中暂停（`pausedFrom=running`），普通 Ready、Ready+发令流程和手动发令禁用；成绩窗口仍开放时仍可“提前结束本轮”。

自动时间轴固定为：第一条 Ready 前 60 秒发送赛前 Notice；第一、二、三条 Ready 位于 T、T+5 秒、T+10 秒；T+15 秒发送 `READY!`，T+20 秒关闭 cheat；关闭 cheat 的真实确认后至少再等 10 秒才发送 `3/2/1/Go`。任一步回显变慢，后续步骤相应顺延。赛程 Bulletin 固定写成 `关卡名 将在 HH:mm 发令`，时间按 UTC+8 计算，但文本不显示日期和时区；改期、延后、达到计分阈值或提前结束都会发送新 Bulletin。

工作模式支持并行运行多个比赛，但规范化后的同一服务器地址同一时刻只允许一个工作运行；地址比较忽略主机名大小写、首尾空白和末尾点号。

### 事故与成绩处理

- “流程动态与注意事项”以中文卡片展示流程里程碑、下一 Ready 计划、成绩窗口、违规排除、阻断、事故和不确定命令；所有卡片统一按真实事件时间倒序排列，已自动处理的旧起跑保护不会因刷新更新时间或长期置顶。
- 红色“重赛本关”在已发布且存在活动运行时始终开放，包括 Go 前、事故、暂停、复核和存在未决命令时；比赛结束或归档后不会重新开放。
- 强制重赛会立即进入当前关 Ready；已有尝试立即退出有效榜单，尚未 Go 时不补造尝试。旧流程动作、权限提示、事故、观察缺口和未决真实命令不再阻断新周期，但其原始状态、成绩、事件和审计不会删除或改写。迟到的旧 Go 只保留证据，只有新周期真实确认的 Go 才创建下一次尝试。
- 强制重赛不能修复客观断线或权限配置；确认面板会明确提示新 Ready 在连接或权限仍不可用时可能再次失败并形成新阻断。
- 外部操作员已经发令而系统仍停在 Ready 时，可用“手动标记当前关已起跑”从确认成功执行时刻建立本关尝试和时限。该入口不把外部日志伪装成系统 Go，不回补此前结果，执行后自动化仍暂停；成绩接收和时限继续。
- “强制重置本关（T-60）”与“强制进入下一关”不依赖 MockClient 连接、权限、事故或未决命令状态。前者清除本关有效成绩并从动作后 60 秒重新安排本关 Ready；后者保留成绩，在动作时立即切换到下一关并把其第一条 Ready 安排在 60 秒后。两者都保留旧证据和审计，不能修复客观连接或权限故障。
- 新比赛默认每关起跑保护从第一条 Ready 持续到权威 Go 后 10 秒（含第 10 秒）；已有比赛保留已保存的窗口配置，发布区显示实际秒数。首次掉线或 fatal error 在 Go 前会中止流程并把第一条 Ready 固定改到事件后 60 秒；在 Go 后会自动作废本次尝试及成绩。两种情况都立即从 T-60 重新准备，掉线原因和处理结果使用一条 Announcement，并以“本关将在一分钟后重新发令，请做好准备。”提示玩家，一分钟准备提醒及保护已使用后缀使用一条 Notice，同时更正 Bulletin；重新发令仍使用普通的同地图 Go。
- 新建比赛默认启用起跑保护，可在发布前配置关闭。控制台始终显示本关保护状态按钮；启用时可经确认手动标记“已使用”或重置为“未使用”，关闭配置时按钮保留但不可操作。
- 当关已经记为 DNF 或排除的玩家不再属于起跑保护对象；其后掉线或 fatal error 只更新连接证据，不会消耗本关保护。正常完赛玩家仍按统一敏感期规则处理。
- `forcenextrestart` 会让下一次 Go 无视地图、作用于服务器所有玩家；Ready 回显中的星号只代表服务器已设置该全局标志，与重赛无关。控制台不会发送该命令，原始命令入口也会拒绝它。
- 起跑保护用过后，该关后续敏感期掉线只记录，不再延时或作废；fatal error 后紧随的 disconnect 会去重。新 Bulletin 和赛前 Notice 都会另起一行注明“本关起跑保护已被使用，后续不再延时。”，提前重连不会缩短这 60 秒。
- 第一条 Ready 前以及保护窗外的玩家掉线，无论人数多少都只更新在线状态和连接历史，不发送“等待重连”通知、不阻断自动化，也不改变 Ready 计划。
- 全局 cheat off 前开启 cheat 视为练习；确认关闭后再次开启只 Notice 一次且不阻断。玩家在权威 Go 时仍开启 cheat，或在 running/tail-intake 中开启/带 cheat 登录或重连，立即按 `cheat-enabled` 写入排行榜排除结果，不只生成注意事项。
- 控制台玩家处置只保留 Kick 和原始命令；裁判 DNF 在成绩页完成。
- Kick 和原始命令仅在工作模式开放，并使用按钮旁的结构化确认。

所有确认都在对应按钮旁完成，不使用浏览器弹窗，也不要求自由文本操作原因。Ready 流程、单次 Ready、手动发令、提前结束、重赛、改期、Kick、原始命令、结束、归档、删除以及成绩修订分别使用独立文案，只说明本次操作和后果。后端仍按动作意图、实际目标关、比赛与 runtime 状态版本、计划或尝试影响生成结构化审计记录；目标或影响变化后的旧确认返回 409，不会继续执行。

## 实时成绩、修订与导出

“成绩”页显示：

- 当前总榜名次、总分和排名变化。
- 每个轮次的名次、得分、DNF 或排除状态。
- 金、银、铜名次的视觉标识。
- 当前最新榜单版本。

成绩页的“实时计分映射”可在比赛发布后修改全部关卡共用的“名次 → 分数”表。保存前会展示结构化影响确认；保存后立即从完整排行榜重算已有单关得分、总分和名次，生成新的榜单版本，并让后续自动成绩和人工名次修订继续使用新映射。发布时的不可变配置快照与旧榜单版本不会被覆盖；运行期映射、审计和榜单在刷新或服务重启后仍会恢复。最后一个非零得分所在名次会成为新的“最后计分名次”；若当前关已经满足新阈值，状态机会立即规划下一关 Ready，但不会撤销已经形成的下一关计划。

人工成绩修订同样不会覆盖原始成绩，而会创建新的榜单版本。当前关仍由自动/现场事件接收时不可编辑；进入下一关第一条 Ready 前 60 秒的准备阶段后，可以修订此前关卡，比赛结束或归档后可以修订全部关卡。确认接口和最终写入都会重新检查这一边界。直接点击可编辑关卡的成绩单元格，可以设置新名次或 DNF；空成绩也可设为 DNF，空成绩也可直接补成有名次结果。设置名次或 DNF 时都可以勾选“其他玩家是否顺延”；顺延时确认面板会列出受影响玩家并按当前运行期计分映射自动重算，不顺延时则直接按当前规则计分。成绩页不能直接填写单关得分或总分。人工修订和后续自动成绩共用连续榜单版本，不会相互覆盖；刷新页面和重启服务后玩家集合及修订仍保留。

cheat、可定位到玩家和关卡的明确 Warning，以及带 `[CHEAT]` 的完赛会标为“排除”，自动记 0 分并顺延其他选手。系统保留后续真实完赛作为证据，但不会伪造 `did not finish` 日志；无法定位玩家或关卡的 Warning 只进入注意事项。只有真实 DNF 和成绩页裁判判定才使用 DNF 状态；关卡超时只关闭成绩接收窗口，不会为未完成玩家补记 DNF。

达到最后计分名次后，系统立即按轮间等待规划下一 Ready（默认 3 分钟），不等待本关剩余时限；下一 Ready 前 60 秒的准备边界到达时关闭上一关成绩窗口并切换当前关。窗口关闭前，第 13 名及以后等零分名次仍会进入排行榜。若该准备边界因改期而延后，上一关窗口最多保留到原关卡时限；即使自动化暂停，既定的 T-60 边界和时限仍会生效，但不会为未完成玩家补记 DNF。

已完赛玩家可以在这段轮间时间进入下一关练习。下一关练习产生的 cheat、Warning、完赛或 DNF 只保留在原始日志中，不会污染仍在接收的上一关成绩，也不会提前处罚下一关。

支持的导出格式：

| 格式 | 推荐用途 |
| --- | --- |
| XLSX | 赛后复核、存档和进一步统计 |
| CSV | 数据处理和其他系统导入 |

页面、复制、CSV 和 XLSX 使用同一张成绩表：`变化｜名次｜总分｜选手｜每关独立列`，单元格文字与页面一致，不会把所有轮次合并到一个字段。“复制表格”会同时写入带前三名颜色、DNF 删除线和排除样式的 HTML，以及兼容普通粘贴的 TSV；浏览器拒绝剪贴板权限时会显示可选中的 TSV 手工复制区。

导出固定到发起操作时的榜单版本，不会在生成过程中混入后续成绩。工作/测试标记写入文件名、XLSX 工作表名和隔离目录，不额外污染表格列。当前界面导出最新版本；历史版本选择界面仍在后续计划中。归档中只保存 CSV 与 XLSX 成绩文件。

## 归档

榜单产生后可在“结束与归档”页选择“结束比赛”“结束并生成归档”或对已结束比赛“仅生成归档”。比赛进入“复核”阶段后会自动转为“已结束”，可直接归档。结束、删除或服务关闭会等待受管 MockClient 完成有界 graceful stop；失败时复用同一套 PID、可执行路径和完整命令行所有权核验，只有确认属于本运行才强制结束进程树。未确认退出时不会丢弃受管句柄、服务器租约或提前报告关闭完成：运行保留为红色阻断，成绩窗口和时限驱动继续，裁判可安全重试硬恢复、删除或关闭。自动复核已经把比赛标记结束时若停止失败，会另行显示红色“MockClient 未确认退出”。每次归档都会创建新版本，不覆盖旧归档，并记录：

- 归档版本和生成时间。
- 归档目录与包路径。
- Manifest 哈希。
- 比赛模式和相关数据版本。

测试模式和工作模式归档相互隔离。正式比赛结束后，建议同时保留 XLSX 导出、归档包和整个数据目录备份。

任何状态的比赛都可通过高风险确认直接删除。删除会先中止全部运行与自动化，再移除比赛业务记录及工作/测试运行目录，但保留已经生成的独立归档包。

## 多标签页与连接状态

- 第一个打开的标签页通常取得控制权。
- 其他标签页默认为只读，可点击顶部“接管”转移控制权。
- 同一时间只允许一个标签页执行裁判写操作。
- 顶部显示“实时重连中”时，写操作会禁用；恢复连接并刷新快照后才能继续。
- 带 `#token=...` 的启动地址用于建立本机会话，不应发布到聊天群或直播画面中。

## 当前限制

- 当前目标是单机、小型赛事闭环，不包含云端账号和多裁判同时操作。
- 已提供逐关编辑、SR/HS 预设和单关计分覆盖；预设后仍可直接编辑，但流程策略和通知模板尚未提供完整可视化编辑。
- 自动登记和显示名映射已具备；改名冲突、身份拆分以及黑白名单控制尚未完成。
- 历史榜单版本选择、修订撤销，以及原始日志的筛选/检索和标准事件诊断仍待完善。
- 工作模式中断恢复必须在目标赛事服务器完成现场彩排后再用于正式比赛。
- “手动标记当前关已起跑”“强制重置本关（T-60）”“强制进入下一关”的用户入口、后端事务、计分与快照恢复链路已在当前源码实现，阶段 4 完整本地自动门禁已通过。2026-07-29 已在空闲的 `2.bmmo.win` 完成 17 条定向协议补测，但该轮没有请求连接恢复，不能把它当成正式双服恢复门禁、20 秒冷却复验或三项恢复动作的现场验收。

### 验证命令

| 命令 | 用途 |
| --- | --- |
| `npm run lint` | ESLint 静态检查 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm test` | Vitest 单元、集成和非功能测试 |
| `npm run test:coverage` | 运行同一组 Vitest 测试并生成文本及 `coverage/index.html` 覆盖率报告 |
| `npm run build` | 构建全部共享包、服务和前端 |
| `npm run test:e2e` | Edge 与 Chrome 浏览器旅程 |
| `npm run test:mock-client` | 真实 MockClient 管道测试 |
| `npm run test:live-probes` | 经双重显式授权后，串行验证 `1.bmmo.win` 与 `2.bmmo.win` 的真实协议及连接恢复 |
| `npm run test:live-work` | `test:live-probes` 的兼容别名 |
| `npm run package:portable` | 生成 Windows 便携包 |
| `npm run test:portable` | 在无系统 Node 环境限时验证便携包，并核对端口与包内进程已回收 |

Playwright 的临时运行产物写入 `.runtime/playwright-results`，不属于项目源码或发布内容。

`npm run test:coverage` 使用与 Vitest 同版本的 V8 provider，并把未被测试导入的生产源码也计入基线。该报告只反映 Vitest 单元、集成和非功能测试；Playwright 浏览器旅程、真实 MockClient、实服探针和 portable smoke 不会自动合并到这份覆盖率中。

便携 smoke 的启动、健康检查、原生 SQLite、进程查询和清理均有硬时限。健康响应必须同时绑定唯一监听 PID 与包内 `runtime/node.exe`；查询失败会明确失败，不能被当成“端口空闲”或“已清理”。测试先用本轮随机令牌优雅关闭服务，必要时才结束已核验的进程树；只有确认 `38623`、包内 Node 和启动器都退出后，才原子写入本轮通过 artifact。

实服门禁会发送通知、Ready、Go、地图注册和自 Kick，并会先通过与健康态手动软重连相同的精确自 Kick/1101 路径制造受控断线，再执行软重连、同名登录拒绝、受管 MockClient 强制关闭及重新认证，只能在两台目标服均获准且空闲时执行。运行前必须同时设置 `BALLANCE_ALLOW_LIVE_COMMANDS=1` 和 `BALLANCE_ALLOW_LIVE_RECOVERY=1`；脚本会在每台服务器先执行 `list`，发现普通玩家或无法唯一建立本机 `*ContestConsole` 连接 ID 时立即中止。恢复探针分别保存新旧连接 ID、MockClient 版本、原始回显和身份释放耗时；两服最大释放时间必须不超过固定 20 秒冷却，否则门禁失败。两台服务器的独立证据及差异汇总写入已忽略的 `test/artifacts/`，任何一台未执行或未通过都不能算作双服门禁通过。

单服定向补跑只证明该次实际覆盖的服务器和协议分支；artifact 中 `recovery.status=not-requested` 时尤其不能据此声称完成双服恢复、20 秒冷却或现场验收。同名 artifact 会被后续运行覆盖，历史结论应另存不可覆盖证据或内容哈希。

### 项目结构

```text
apps/
  server/        Fastify 本机 API、持久化、归档和 MockClient 适配
  web/           React 裁判控制台
packages/
  contracts/     前后端共享类型、配置和动作契约
  core/          状态机、计分、身份和榜单修订
  testkit/       虚拟时钟和场景运行器
docs/            需求、规则和开发进展
scripts/         开发、启动、打包和验证脚本
server-windows/  BallanceMMO Windows 运行文件
test/            夹具、单元、集成、浏览器和非功能测试
```

服务端以 `CompetitionService` 作为 API 门面；工作模式进程/命令/名单对账、测试模式场景/虚拟时钟、榜单修订、裁判动作和审计日志分别由独立服务负责。模块只通过窄接口交换配置、持久化、事件和快照，HTTP API 与 SQLite 格式不因这次拆分改变。

## 安全边界

- 服务仅绑定 `127.0.0.1:38623`，不应直接暴露到公网。
- 控制台通过一次性启动 token 建立本机会话。
- 测试模式不联网、不启动真实 MockClient、不发送真实命令。
- 工作和测试数据在导出与归档中明确区分。
- 启动器只会结束已识别为本项目的旧进程，不会自动结束未知端口占用者。
