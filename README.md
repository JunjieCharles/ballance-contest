# Ballance 比赛控制台

Ballance 比赛控制台是一套在 Windows 本机运行的裁判工具，用于托管 BallanceMMO MockClient、控制比赛流程、处理事故与重赛、实时查看和修订成绩，并导出或归档比赛数据。

当前版本：`0.1.0-dev`

> 当前版本适合测试演练、目标服务器彩排和受控的小型赛事试运行。工作模式已经接通真实 MockClient，但正式使用前仍应完成目标服务器的账号、网络和完整流程彩排。具体状态见[开发进展](docs/development-progress.md)。

## 主要功能

- **工作模式**：托管真实 MockClient，读取比赛日志，串行发送命令并记录回显。
- **测试模式**：从场景卡片创建测试运行，通过时间线、虚拟时钟和故障按钮演练比赛。
- **裁判控制**：通知、Ready、关闭 cheat、手动 Go、改期、延时、结束轮次、重赛、作废/恢复尝试、标记 DNF、Kick、Crash 和高级命令。
- **实时成绩**：完赛、DNF 和人工修订后生成新的榜单版本，页面实时刷新名次与积分。
- **导出归档**：导出 XLSX、CSV、HTML、TSV，生成带版本与哈希记录的比赛归档。
- **本地持久化**：比赛、配置、运行快照、命令审计、榜单和归档记录保存在 SQLite 中。
- **操作保护**：高风险动作要求确认原因；断开实时连接时禁止写操作；其他浏览器标签页默认只读。

## 快速开始

### 运行 Windows 便携包

便携包自带 Node.js 和运行依赖，使用电脑无需预装开发环境。

1. 打开 `dist/portable/BallanceContestConsole`。
2. 双击 `Start-ContestConsole.cmd`。
3. 保持启动窗口运行，浏览器会自动打开控制台。
4. 首次进入后，先新建一场测试模式比赛熟悉操作。

控制台地址形如：

```text
http://127.0.0.1:32113/#token=...
```

启动器会自动关闭上一个由本项目启动的控制台实例并释放 `32113`。如果端口由其他程序占用，启动器会显示进程信息并停止启动，不会误杀无关程序。

### 数据保存位置

默认数据目录：

```text
%LOCALAPPDATA%\BallanceContestConsole
```

其中包含 SQLite 数据库、日志、导出和归档。正式比赛前建议备份此目录；比赛运行期间不要手工修改其中的文件。

## 第一次使用

### 1. 新建比赛

在左侧“比赛”区域填写名称并选择模式：

| 模式 | 用途 | 是否连接真实服务器 |
| --- | --- | --- |
| 测试模式 | 裁判培训、流程演练、计分验证、故障演练 | 否 |
| 工作模式 | 真实比赛和目标服务器彩排 | 是 |

模式在比赛创建后不可互换。测试数据会带有明显标识，避免与正式比赛产物混淆。

### 2. 配置并发布

打开“比赛配置”页：

1. 填写比赛名称、服务器和裁判名。MockClient 会自动以 `*裁判名` 旁观登录。
2. 在“玩家”页加入参赛者。
3. 检查默认 SR1-SR13 轮次、模式、时限和计分。
4. 点击“发布比赛”。

发布会执行字段校验并保存不可变配置快照。发布后不能继续编辑草稿，因此应在发布前仔细检查服务器和参赛名单。

当前前端尚未提供轮次、计分、流程策略和通知模板的完整编辑器。如正式赛事不使用默认配置，应先在彩排中确认配置方案，参见[开发进展中的 P0 项](docs/development-progress.md#p0正式赛事前)。

## 测试模式操作

测试模式不需要粘贴 JSON，普通使用流程如下：

1. 新建测试模式比赛，加入参赛者并发布。
2. 打开“测试”页，在“场景库”中选择场景卡片。
3. 查看事件时间线，点击“创建测试运行”。
4. 使用“逐事件”观察每个事件，或使用“播放到底”完成整个场景。
5. 使用 `+15 秒`、`+3 分钟` 推进虚拟时钟。
6. 通过故障按钮模拟服务器断线、进程退出、选手掉线、选手崩溃或时钟跳变。
7. 切换到“控制台”处理阻断、事故、重赛和 DNF。
8. 在“成绩”页查看实时榜单并导出结果。

“高级 JSON 导入”保留给场景开发和特殊回归，不是日常测试入口。

测试模式中的命令只记录为模拟结果，不会联网、启动真实 MockClient 或发送真实服务器命令。Kick、Crash 和原始命令等真实副作用操作会禁用，相关异常应通过故障注入演练。

## 工作模式操作

### 赛前准备

确认便携包的 `server-windows/` 中存在以下文件：

- `BallanceMMOMockClient.exe`
- `GameNetworkingSockets.dll`
- `libcrypto-3-x64.dll`
- `libprotobuf.dll`
- `yaml-cpp.dll`

在目标服务器上先确认：

- 裁判账号有发送通知、Ready、Go、Kick、Crash 等所需权限。
- 服务器地址和网络可达。
- 裁判名不会与其他裁判客户端冲突；旁观模式由控制台强制开启。
- 日志目录可写且磁盘空间充足。

### 启动比赛

1. 新建工作模式比赛，完成配置和参赛名单后发布。
2. 打开“控制台”，点击“启动 MockClient”。
3. 在“命令审计”中确认连接和命令回显。
4. 点击“启用自动化”，或保持暂停并由裁判手工推进。
5. 观察顶部阶段、当前轮次、榜单版本、自动化状态和下一 Ready 时间。

如果命令已经发出但没有收到可识别回显，命令会进入 `uncertain`，系统不会盲目重发。此时应暂停自动化，检查服务器现场后再由裁判决定。

## 裁判控制台

### 流程操作

| 操作 | 作用 | 注意事项 |
| --- | --- | --- |
| 发送通知 | 向比赛服务器发送裁判文本 | 发送前检查目标比赛和文本 |
| Ready | 进入准备流程 | 工作模式会等待真实回显 |
| 关闭 cheat | 关闭服务器 cheat | 开赛前确认执行成功 |
| 手动 Go | 跳过自动时序并发出 Go | 高风险操作，需要确认原因 |
| 延长 1 分钟 | 延后当前等待时间 | 会改变后续时间计划 |
| 改期 | 设置新的 Ready 时间 | 使用本机显示的日期时间 |
| 提前结束本轮 | 结束当前轮次 | 确认未接收成绩和 DNF 处理完毕 |

### 事故与成绩处理

- “阻断与事故”会显示系统无法安全自动处理的问题。
- “确认重赛”只应在核对事故目标和受影响选手后使用。
- “作废尝试”不会删除原始事件，而是改变尝试有效性并生成后续状态。
- “恢复尝试”用于撤销错误的作废处理。
- “标记 DNF”需要选择目标选手并填写原因。
- Kick、Crash 和原始命令仅在工作模式开放，并要求高风险确认。

每次操作都应填写能在赛后复核的原因，避免使用“测试”“临时”等无法解释裁决的文字。

## 实时成绩、修订与导出

“成绩”页显示：

- 当前总榜名次、积分和排名变化。
- 每个轮次的名次、积分或 DNF 原因。
- 金、银、铜名次的视觉标识。
- 当前最新榜单版本。

人工修订不会覆盖原始成绩，而会创建新的榜单版本。操作时选择选手和轮次，填写名次、积分及复核原因，再确认生成修订版本。

支持的导出格式：

| 格式 | 推荐用途 |
| --- | --- |
| XLSX | 赛后复核、存档和进一步统计 |
| CSV | 数据处理和其他系统导入 |
| HTML | 直接浏览和打印 |
| TSV | 粘贴到表格软件 |

导出固定到发起操作时的榜单版本，不会在生成过程中混入后续成绩。当前界面导出最新版本；历史版本选择界面仍在后续计划中。

## 归档

榜单产生后可在“归档”页点击“生成归档”。每次归档都会创建新版本，不覆盖旧归档，并记录：

- 归档版本和生成时间。
- 归档目录与包路径。
- Manifest 哈希。
- 比赛模式和相关数据版本。

测试模式和工作模式归档相互隔离。正式比赛结束后，建议同时保留 XLSX 导出、归档包和整个数据目录备份。

## 多标签页与连接状态

- 第一个打开的标签页通常取得控制权。
- 其他标签页默认为只读，可点击顶部“接管”转移控制权。
- 同一时间只允许一个标签页执行裁判写操作。
- 顶部显示“实时重连中”时，写操作会禁用；恢复连接并刷新快照后才能继续。
- 带 `#token=...` 的启动地址用于建立本机会话，不应发布到聊天群或直播画面中。

## 当前限制

- 当前目标是单机、小型赛事闭环，不包含云端账号和多裁判同时操作。
- 尚未提供轮次、计分、流程策略和通知模板的完整可视化编辑。
- 玩家身份关联、拆分和修正界面尚未完成。
- 历史榜单版本选择、修订撤销和独立日志/事件页仍待完善。
- 工作模式中断恢复必须在目标赛事服务器完成现场彩排后再用于正式比赛。
- 不提供正式直播观察端、完整黑白名单管理或公网部署。

完整进度和发布前清单见[开发进展](docs/development-progress.md)。

## 从源码运行

以下内容面向开发者。普通裁判使用便携包即可。

### 环境要求

- Node.js `>=24.18.0 <25`
- npm
- Windows，用于工作模式、MockClient 管道和便携包验证
- Edge 或 Chrome，用于端到端测试

```powershell
npm ci
npm run build
npm run start -w @ballance/server
```

终端会输出带启动 token 的控制台地址。

开发模式：

```powershell
npm run dev
```

如果系统 `PATH` 中没有 Node.js，可使用仓库本地运行时：

```powershell
$env:PATH = "$PWD\.tools\node-v24.18.0-win-x64;$env:PATH"
npm run build
```

### 验证命令

| 命令 | 用途 |
| --- | --- |
| `npm run lint` | ESLint 静态检查 |
| `npm run typecheck` | TypeScript 类型检查 |
| `npm test` | Vitest 单元、集成和非功能测试 |
| `npm run build` | 构建全部共享包、服务和前端 |
| `npm run test:e2e` | Edge 与 Chrome 浏览器旅程 |
| `npm run test:mock-client` | 真实 MockClient 管道测试 |
| `npm run package:portable` | 生成 Windows 便携包 |
| `npm run test:portable` | 在无系统 Node 环境验证便携包 |

Playwright 的临时运行产物写入 `.runtime/playwright-results`，不属于项目源码或发布内容。

### 生成便携包

打包前需要完成构建，并在 `.tools/node-v24.18.0-win-x64` 准备 Node 运行时：

```powershell
npm run package:portable
```

输出目录：

```text
dist/portable/BallanceContestConsole
```

## 安全边界

- 服务仅绑定 `127.0.0.1:32113`，不应直接暴露到公网。
- 控制台通过一次性启动 token 建立本机会话。
- 测试模式不联网、不启动真实 MockClient、不发送真实命令。
- 工作和测试数据在导出与归档中明确区分。
- 启动器只会结束已识别为本项目的旧进程，不会自动结束未知端口占用者。
