# Ballance 比赛控制台前端需求文档

> 文档状态：需求基线草案  
> 适用平台：Windows 本机浏览器  
> 配套后端文档：[contest-console-backend-requirements.md](./contest-console-backend-requirements.md)  
> 参考规则：[rule.md](./rule.md)  
> 成绩表样例：[scoreboard.xlsx](./scoreboard.xlsx)

## 1. 文档目标与前端边界

### 1.1 产品目标

前端为 Ballance 比赛裁判提供本地网页控制台，用于比赛配置、玩家监控、自动流程、异常介入、实时成绩管理、测试演练和归档操作。

前端不直接访问 `BallanceMMOMockClient.exe`、比赛日志、SQLite 或归档文件。进程控制、日志解析、计时、比赛状态机和计分均由本机后端完成；前端通过 HTTP 和 WebSocket 展示后端的唯一权威状态并提交操作意图。

### 1.2 已确认决策

| 项目 | 决策 |
| --- | --- |
| 运行形态 | 浏览器中的本地网页 + Windows 本机服务 |
| 后端地址 | 固定为 `http://127.0.0.1:38623` |
| 自动化权限 | 裁判启用自动控制后，正常规则流程可全自动，包括正常起跑 |
| 关键介入 | 手动 Go、重赛本关、修改已结算名次等操作必须确认 |
| 默认比赛 | 原版关卡 SR 1–13 |
| 默认比赛类型 | 小型 |
| 默认服务器 | `1.bmmo.win`；提供 `0.bmmo.win`、`1.bmmo.win`、`2.bmmo.win` 快捷选项，均不填写端口 |
| 服务器控制身份 | 固定 `ContestConsole`，不可配置 |
| 正式系统裁判来源 | 本机托管的 MockClient 是唯一裁判，不提供多裁判或远程交接 |
| 运行模式 | 仅工作模式和测试模式；发布后不可切换 |
| 测试安全 | 测试模式不启动真实 MockClient、不联网、不发送真实命令 |

### 1.3 前端范围

- 比赛列表、新建向导、完整配置、发布和状态管理。
- 比赛控制台、自动流程状态、下一动作、计时、阻断和事故处理。
- 在线玩家、参赛名单、连接状态、身份冲突、角色和备注。
- 单轮成绩、实时总榜、人工修订、复制和导出。
- 原始日志、标准化事件和命令回执查询。
- 测试模式的场景模拟、静态/增长日志、播放控制和场景故障计划。
- 归档创建、进度、校验结果和历史归档查看。

### 1.4 前端不负责

- 不在浏览器内启动进程、读写本地日志或计算权威比赛状态。
- 不根据浏览器计时器决定 Go、关卡超时或自动流程动作。
- 不直接拼接或执行 MockClient 命令。
- 不自动裁决录像申诉、代打、故意利用 bug 等人工事项。
- 不直接调用腾讯文档私有接口；使用标准剪贴板和文件导出兼容。
- 不提供多裁判协同或比赛中裁判交接；工作模式仅接受本机控制端发令。
- 不提供正式观察直播或独立回放模式。
- 不依赖服务端内部运行管理器或内存结构；服务端模块拆分不得改变前端使用的 HTTP、WebSocket、动作矩阵和快照契约。

## 2. 用户与运行模式

### 2.1 用户角色

- **裁判/发令员**：配置比赛、启用自动化、处理异常、批准关键介入。
- **计分员**：查看和修订成绩、导出榜单；首版可与裁判为同一人。
- **只读观察者**：后续能力，只查看状态和成绩；首版本机页面不单独实现账号系统。

### 2.2 运行模式

#### 工作模式

后端拥有真实 MockClient 子进程，页面开放与当前状态相符的完整控制能力。顶栏持续显示“工作模式”、服务端、控制身份和连接状态。工作模式没有外部日志观察入口。

#### 测试模式

测试模式统一承载假 MockClient、虚拟时钟、静态/增长日志、播放和场景故障计划。页面使用固定区别色及“测试数据”水印，禁止真实联网和命令；模拟动作必须明确显示为模拟结果，不能伪装成服务器成功。

模式在比赛创建时选择，发布后不可切换。测试配置可以复制成新的工作模式草稿，但事件、成绩、事故和测试状态不得复制。

## 3. 信息架构

### 3.1 一级页面

- **比赛列表**：新建、复制、继续、结束、归档、创建测试运行。
- **比赛配置**：基本信息、轮次、计分、玩家策略、流程策略、通知模板、发布检查。
- **比赛控制台**：当前轮次、自动化、计时、玩家摘要、实时排名、事故和关键事件。
- **玩家**：自动登记参赛者、游戏内玩家 ID、排行榜显示名映射、在线状态和连接历史。
- **成绩**：单轮结果、总榜、待复核、人工修订、复制和导出。
- **日志与事件**：原始日志、标准化事件、命令回执和筛选定位。
- **测试控制台**：从玩家行为/故障场景创建测试运行并显式推进虚拟时钟；自动化只在比赛控制台启停，故障由场景按阶段触发；JSON 与逐事件日志回放不作为裁判界面入口。
- **归档与设置**：归档包、MockClient 路径、默认服务器、版本和诊断。

### 3.2 导航状态

- 比赛进行中时，所有比赛内页面固定显示当前轮次、比赛状态、本轮起跑/预计起跑时间、本轮截止时间、自动化状态和未处理事故数量；已有非作废尝试时显示实际 `goAt`，不得继续把估算时间冒充为实际起跑。
- 离开控制台页面不会停止后端自动化；导航前只在存在未提交表单时提示。
- 浏览器刷新后从后端恢复完整快照，不出现“看似重新开始”的本地空状态。
- 重复点击当前已选比赛时保持现有快照并刷新数据，不得先清空为“请选择或新建比赛”。
- 同一浏览器打开多个控制标签页时，后打开页面默认只读；取得控制权需要明确操作。
- 前端始终连接固定地址 `http://127.0.0.1:38623`，不得在开发热更新时自动切换到随机端口或残留后端实例。

## 4. 前端状态与数据同步

### 4.1 权威状态

- 比赛状态、计时、命令结果和成绩版本全部以后端为准。
- 前端可以做表单草稿和视觉倒计时，但不得用本地倒计时触发业务动作。
- 页面显示后端状态版本、最后事件序号和最后同步时间。
- WebSocket 断开时立即显示“数据可能已过期”，禁用写操作并自动重连。
- 重连后先获取完整快照，再从事件序号继续增量；发现序号缺口时重新获取快照。
- 同一批自动流程产生的高频日志、动作和榜单事件必须合并刷新；不得为每条事件各发一次完整比赛列表与 snapshot 请求，合并后仍以最终权威快照为准。

### 4.2 动作状态

每个操作显示明确状态：待确认、排队、已发送、已回显确认、失败、超时或结果不确定。不能把按钮点击成功提示成服务器执行成功。

对 Go、重赛、Kick、原始命令等不自动重试的动作，若后端返回“不确定”，页面必须进入阻断状态并引导裁判核对现场。

### 4.3 通用反馈

- 表单错误定位到具体字段并保留其他输入。
- 后端业务冲突显示最新状态及冲突原因，不自动覆盖。
- 普通成功使用短暂提示；事故、阻断和不确定命令使用持久提示。
- 所有时间同时说明时区；测试日志中区分日志时间、接收时间和通知文本。

## 5. 比赛列表与新建配置

### 5.1 比赛列表

每项显示比赛名称、日期、服务器、模式摘要、当前轮次、状态、最后修改时间和归档状态。支持按状态、日期和名称筛选。

允许的操作：

- 新建比赛。
- 从已有比赛复制为新草稿，不复制运行事件和成绩。
- 继续未结束比赛。
- 打开已结束比赛复核或归档。
- 创建测试运行并选择模拟场景、静态日志或增长日志输入。

### 5.2 新建向导

新建表单默认选择工作模式；测试模式是裁判演练时主动选择的备选项。模式在创建后不可切换。

按以下步骤组织，但允许返回修改：

1. 基本信息与服务器。
2. 比赛模板和轮次。
3. 计分方案。
4. 参赛者和身份策略。
5. 自动流程与异常策略。
6. 通知模板。
7. 发布检查与确认。

草稿自动保存到后端。未通过发布校验时可以退出，但不能启用自动控制。

### 5.3 基本信息表单

| 配置项 | 默认值/交互 |
| --- | --- |
| 比赛名称 | 必填，用于页面、导出和归档 |
| 比赛日期与时区 | 本机日期、`Asia/Shanghai`；可修改 |
| 服务器控制身份 | 只读显示 `ContestConsole`；后端最末端始终强制以 `*ContestConsole` 旁观登录 |
| 服务器 | 默认 `1.bmmo.win`；三个 `bmmo.win` 预设均不显示或要求端口，自定义地址可按需要包含端口 |
| 比赛类型 | 默认小型，也可选择大型、自定义 |
| 归档位置 | 展示后端解析后的路径，不允许自由输入危险相对路径 |

UUID 默认只显示是否已配置及末尾片段，避免普通页面泄露完整值。

### 5.4 轮次编辑器

提供 `SR 1–13`、`HS 1–13` 整体替换预设，并保留“保存关卡列表”按钮；预设替换直接落盘，逐关编辑先改后保存，未保存的关卡修改会在发布检查中被拦截。配置区的持久化写入使用单写锁：从请求开始到对应新快照实际落地期间禁用其他保存和预设入口，同一事件周期内的第二次写入也必须明确拒绝，不能让两个请求携带同一旧状态版本并在重挂载后隐藏 409。
- 每轮从“官图 SR / 官图 HS / 自制图 SR / 自制图 HS”四种组合中选择。官图只编辑关卡号，名称自动显示为 `SR1`、`HS1`；自制图编辑显示名称和完整 32 位 MD5，不显示固定为 `0` 的内部关卡号。
- 轮次支持新增、复制、删除；排序只使用最左侧三横杠手柄，拖动过程按稳定轮次 ID 识别源和目标，完整卡片跟随指针，目标位置显示与源卡等高的占位，保存后刷新仍保持顺序。官图行的复制/删除操作区不得与单关计分输入重叠。
内置小型和大型两套规则，并支持直接逐名次计分：
- 默认限时为 10 分钟；SR13、HS12、HS13 自动预填 15 分钟，并允许覆盖。
当前界面支持小型和大型计分预设，点击预设后先展示确认面板，确认后整体覆盖当前计分并同步到全部关卡。之后仍可继续直接编辑各名次，但手工改动需要点击“保存计分规则并覆盖单关配置”才会落盘并应用到全部关卡。每关可独立编辑，未保存的关卡修改会在发布检查中被拦截。最后计分名次只读展示并随计分表自适应。统一尾部得分和负分开关尚未提供可视化入口；负分默认关闭。
- 已开始的轮次显示锁定状态，只能通过有审计的修订入口变更。
原始 Client 日志不嵌入任一业务页，而以全局右下角悬浮窗提供；切换比赛时随比赛上下文刷新。窗口默认展开，可拖拽、双向缩放、手动刷新和最小化，并提供左上角缩放手柄，保持足够小的初始尺寸，避免覆盖主要流程入口。新日志到达前若视口已在底部则继续跟随；裁判已滚到其他位置时保留原滚动位置。工作模式展示真实 MockClient 行；测试模式的模拟玩家与模拟裁判行复用真实 `[MM-DD HH:mm:ss]` 前缀以及登录、Ready、cheat、Go、完赛和 DNF 句式。
### 5.5 计分编辑器

内置小型和大型两套规则，并支持自定义逐名次计分：

- 小型：`20, 15, 12, 10, 8, 6, 5, 4, 3, 2, 1, 1`，第 13 名起为 0 分。
- 大型：`30, 24, 21, 18, 16, 14, 12, 10, 8, 6, 5, 4, 3, 2, 1`。
- “最后计分名次”由计分表最后一个非零得分自动推导；小型为 12、大型为 15，该名次之后、DNF 和排除结果默认 0 分。

当前界面支持小型、大型和自定义逐名次计分；每关可独立编辑，“应用计分方案到全部关卡”会明确提示覆盖各关自定义计分。最后计分名次只读展示并随计分表自适应。统一尾部得分和负分开关尚未提供可视化入口；负分默认关闭。

### 5.6 流程策略

前端允许配置并解释以下项：

- 公告提前量，默认 5 分钟。
- 单次延时上限，默认 5 分钟。
- 固定发令节奏：T/T+5/T+10 三次 Ready，T+15 `READY!`，T+20 cheat off，确认后至少 10 秒再倒数。
- 起跑保护窗口，默认 Go 后 15 秒。
- 是否启用起跑保护，默认开启；发布前可关闭。关闭后控制台仍展示保护状态控制，但必须禁用并说明来自比赛配置。
- 玩家掉线只在从第一条 Ready 到权威 Go 后 15 秒的敏感期触发每关一次的起跑保护；其余时段只记录。
- 达到最后计分名次后的下一轮安排：立即按默认 3 分钟轮间休息计划，不等待本关剩余时限；下一轮第一条 Ready 前 60 秒的准备边界前继续接收上一轮有效成绩。
- 上一轮成绩接收截止点为“下一轮 T-60 准备边界”和“上一轮关卡时限”两者中更早者；截止后的上一关完赛、DNF、Warning 和 `[CHEAT]` 完赛保留在原始日志中，但不计分、不排除且不生成违规注意事项。
- 普通通知回显超时只显示黄色注意事项；关键流程命令始终不自动重试。
- 连接状态按后端六态展示为“正在连接、正在认证、健康、可疑、恢复中、已阻断”。`Connected to server OK` 只表示进入认证，必须等登录拒绝观察窗口结束并由本连接的显式 `list` 完整收口、唯一确认 `*ContestConsole` 新连接 ID 后才显示健康；此前普通通知、Ready、cheat off、Go 不可用，也不得显示为已回显确认。`Login denied`、1002、2000 要明确显示为认证失败。

每个策略旁显示其规则影响，而非只显示技术字段。

### 5.7 通知模板

支持编辑和预览赛前 Bulletin、Ready、起跑保护延时、起跑中止、重赛、本轮结束、下一轮和比赛结束模板。

模板变量以可插入标签展示，包括比赛名、关卡、模式、计划时间、剩余时间和玩家名。预览必须以最终发送文本为准，并显示长度校验。

### 5.8 发布检查

发布前集中显示：

- 服务器、控制身份、日期和时区。
- 轮次顺序、地图、模式和限时。
- 计分方案和提前结束条件。
- 最后计分名次、达到该名次后的轮间休息及上一轮成绩接收截止策略。
- 显示名映射冲突；参赛者允许为空并在运行时自动登记。
- 自动化、掉线、重赛和迟到策略。
- 未填写或有风险的项目。

检查未通过时必须在发布按钮附近逐项显示可执行的问题说明；后端返回的校验明细不得折叠成单一“发布检查未通过”。

发布后配置生成版本号。对已开始比赛的规则修改必须经过修订流程。

## 6. 比赛控制台

### 6.1 主页面布局

在常见 1366×768 屏幕上无需滚动即可看到：

- MockClient、服务器、权限、版本和日志健康状态；连接卡同时显示六态状态、进程/连接 generation、当前裁判连接 ID、恢复步骤和最近服务端证据，不向裁判暴露裸内部对象。
- 当前轮次、地图、模式、尝试号和比赛状态。
- “本关 Ready（UTC+8）”显示 `currentStageId` 对应关卡第一次 Ready 的计划或实际时间；“下一关 Ready（UTC+8）”只在 T-60 边界前已经为不同的下一关建立计划时显示，否则明确为“未设置”。边界到达后 `currentStageId` 原子切换，同一计划改显示在“本关 Ready”，不得仍把旧关称为当前关，也不得显示 Go 估算时间。
- Go 后权威计时、关卡限时、下一自动动作和倒计时。
- 在线、掉线、比赛中、完赛、DNF 和待复核人数。
- 自动化启用/暂停、通知、改期和事故入口。
- 单轮排名前列、总榜摘要和最近关键事件。

详细玩家、完整成绩和日志可在下方区域或对应页面展开。

### 6.2 自动化启用

页面提供“启动自动化”流程，展示后端赛前检查：

- MockClient 已完成本连接的唯一身份认证并处于健康状态，以及版本、权限和控制身份。
- 服务器、比赛时间和时区。
- 轮次、计分和通知模板；参赛者不要求预登记。
- 身份冲突及其他阻断。

确认启动后，页面立即显示首轮关卡、默认 3 分钟后的第一条 Ready 计划和已发送的 Bulletin。Bulletin 固定为 `关卡名 将在 HH:mm 发令`，`HH:mm` 按 UTC+8 计算但不显示日期或时区；第一条 Ready 前 60 秒发送完整赛前 Notice。三次 Ready 位于 T/T+5/T+10，T+15 发送 `READY!`，T+20 关闭 cheat，从真实确认再等待至少 10 秒后进入 `3/2/1/Go`；前一步回显变慢时后续相应顺延。工作和测试模式默认都按 1× 真实时间持续调度同一状态机；测试模式不能自动跳过边界、轮间等待或关卡时限，正常流程只有权威 Go 创建尝试，当前 Ready 无尝试时的裁判“手动标记当前关已起跑”是唯一显式例外。虚拟时钟快进必须是裁判明确点击的演练操作。页面始终显示下一动作、可读时间、测试虚拟时钟和固定可见的暂停按钮。

自动化暂停或一般阻断时，原按钮改为“恢复自动化”；尚未关闭的成绩接收窗口和当前关时限继续运行，既定的下一关 T-60 准备边界也继续推进。恢复沿用暂停前阶段和计划，不重新开始 3 分钟等待，也不重新打开已关闭的旧窗口。若存在未决命令，页面先按命令逐条显示“确认已执行”和红色“执行重发”：前者不发送，后者创建新的命令审计并等待新回显，原不确定审计始终保留；全部处理后才能恢复。

### 6.3 比赛状态展示

使用明确状态而非仅用颜色：

`草稿 → 已发布 → 大厅/练习 → 准备检查 → Ready → 倒计时 → 比赛中 → 本轮结算 → 轮间准备 → 比赛复核 → 已结束 → 已归档`

事故/暂停作为可从 Ready、倒计时或比赛中进入的独立状态。状态卡说明进入时间、触发原因和允许的下一操作。

### 6.4 阻断展示

自动起跑被阻断时，页面必须列出每个原因；真实阻断使用红色，黄色只表示注意事项。实际阻断限于：

- MockClient/服务器不可用或权限不足。
- Ready、cheat off、Go 或其他会改变现场状态的真实命令失败/结果不确定，或存在跨权威 Go 的观察缺口。
- 当前关地图映射或事件归属无法唯一建立。
- 本机休眠恢复或时间异常跨过不能安全补发的 Go 边界。

玩家普通掉线、cheat 提醒/排除、Warning、名单汇总差异、已自动处理的起跑保护和手动暂停均不阻断。阻断期间尚未关闭的成绩接收窗口、关卡时限、T-60 关卡边界和可用的定期 `list` 保持运行；每个红色阻断项都必须在旁边提供自动复检、命令处置、重连/重启运行或继续/重赛入口。

工作模式把连接生命周期与比赛现场恢复分开显示。连接控制区提供两个不同动作：“软重新连接”要求当前 MockClient 重新建立服务器连接；若当前仍健康，确认文案必须说明会先精确自 Kick 本机 `*ContestConsole`、核对原因一致的 1101 服务端回显，再发送唯一一次 `reconnect`。“重启 MockClient”执行有界停止、精确所有权核验、必要时强制结束受管进程树、冷却、启动新进程和重新认证。两者分别服从后端动作矩阵，不得共用按钮或把硬重启伪装成软重连；两者都使用高风险内联确认，确认令牌绑定服务器、当前受管 PID、进程 generation 和连接 generation，任一项变化立即关闭旧确认。相同幂等键的在途请求复用同一操作，页面不得因重复点击显示两套恢复。自动恢复进行中显示当前恢复步骤和就地禁用原因，失败后保持红色阻断但继续开放可用的人工动作。测试模式只显示“模拟恢复连接”。连接恢复成功后事故解除但“恢复自动化”仍需裁判点击。只要比赛已发布且存在活动运行，“重赛本关”始终保留并可用。

地图注册在同一进程中断后不得显示“正在自动重试”；自动恢复应明确转入硬重启，并只在新进程重新认证后展示新一轮注册。身份已显示健康但地图注册尚未完成时，普通现场动作、自动化派发和全部“执行重发”仍禁用并显示地图注册原因；本地“确认已执行/确认不再执行”继续可用。服务器明确返回权限不足时直接显示红色权限阻断和修复方向，不显示软重连/硬重启循环可以自动解决权限。

“流程动态与注意事项”以中文卡片展示流程里程碑、下一 Ready 规划、成绩窗口、违规排除、阻断、事故和不确定命令，不直接渲染 JSON。卡片严格按后端提供的真实事件时间倒序展示，不按类别或严重度额外置顶；刷新快照不得改变同一事件的显示时间。阻断项应区分“等待后端自动恢复”和“需要裁判处理”，并提供对应入口；不确定命令按原动作逐条展示，不使用会掩盖差异的批量确认。

未确认面板同时覆盖自动流程命令和其他会改变现场状态的真实命令。`uncertain` 提供“确认已执行/执行重发”，明确 `failed` 提供“确认不再执行/执行重发”；确认摘要显示原命令、状态和“原记录永久保留”，重发结果若仍未决则出现为新的一行。只要高风险命令已尝试写入 stdin，即使写回调返回错误也按 `uncertain` 展示；连接 generation 切换时，尚未写入的旧代流程动作保持“已取消”且不可重发为原队列续体，旧代证据不能让新代命令显示成功。连接不是 `healthy` 或当前进程仍在注册地图时，本地“确认已执行/确认不再执行”仍可用，但所有“执行重发”必须禁用并显示对应的身份核验或地图注册原因；达到业务就绪后才重新开放。服务重启后已处置项不得重新冒出。普通通知及手动 `list`、`listmap`、`scores` 等只读命令的失败/超时只显示黄色注意事项，不进入该面板；明确连接或权限故障除外。定期在线名单 `list` 不完整或汇总不符时保留上一份完整参与者状态，不展示半批名单，并把问题作为连接健康事故展示一次自动两级恢复及其后的人工动作。

后端动作矩阵是按钮可用性的唯一依据；禁用按钮就地显示原因，启用按钮的确认面板展示具体影响。至少遵循：

- 比赛处于草稿时，所有裁判流程按钮必须禁用并提示“请先发布比赛配置”；仅保留“删除比赛”可用。
- 每个关卡动作都以 `ActionAvailability.targetStageId` 作为唯一展示和提交目标，前端不得用 `currentStageId`、按钮所在分组或旧快照自行推断；尾部接收及从尾部接收暂停时，Ready 流程、手动 Ready、关闭 cheat 和手动 Go 均显示已规划的下一关。
- “进入 Ready+发令流程”在大厅、准备、重赛准备或已规划下一关的尾部接收期且无阻断时可用；点击后第一条 Ready 改为 1 分钟后，立即进入目标关 T-60 准备边界并发预告。从比赛中暂停（`pausedFrom=running`）时禁用。
- “手动 Ready”只发送后端目标关的一次 Ready，不改变阶段、计划、Bulletin 或自动进度；`pausedFrom=running` 时禁用。
- “关闭 cheat”只发送命令且不改计划，成功回显绑定目标关。
- 手动发令不要求 Ready 序列或等待计划时间；目标关已有关闭 cheat 确认、连接/权限正常且无未决命令时可用，仍显示 cheat 的玩家不阻断并在权威 Go 时排除。只有权威 Go 后更新本关发令与最晚结束时间；`pausedFrom=running` 时禁用。
- Ready 延后/改期只在已有计划的赛前等待、准备、尾部接收或重赛准备阶段可用。
- 关卡时限延长/改期和提前结束只在比赛中或尾部接收且成绩窗口开放时可用；从比赛中暂停且窗口仍开放时，提前结束本关继续可用。
- “重赛本关”是红色强制恢复入口：只要比赛已发布、尚未结束且存在活动运行和当前关，就在大厅、准备、Ready、倒数、比赛、尾部接收、事故、暂停和复核阶段保持可用，不受任何阻断、故障、观察缺口或未决命令影响。
- 草稿、无活动运行、已结束和已归档时，“重赛本关”仍保留在流程控制区但禁用并就地显示原因；不得从布局中消失。
- “手动标记当前关已起跑”只在当前 Ready 且没有非作废尝试时开放；确认说明从动作执行时刻开始计算 `goAt` 和本关时限、不发送服务器命令、不回放外部 Go 时间、不回补此前结果。成功后页面显示实际起跑与截止时间，并明确自动化仍暂停。
- “强制重置本关（T-60）”在已发布活动运行中始终保留并可用，不受连接、权限、事故、观察缺口或未决命令影响；确认说明本关有效尝试和成绩将退出当前榜、旧证据保留，并从动作时刻安排 60 秒后的本关第一条 Ready。
- “强制进入下一关”在非末关的已发布活动运行中始终保留并可用，同样不受现场阻断；按钮目标必须是后端给出的下一关。确认说明动作时立即关闭当前窗口但保留成绩、原子切换当前关并开放旧关修订，下一关第一条 Ready 位于 60 秒后。末关、结束和归档的禁用完全服从后端矩阵。
- 上述三个按钮与“重赛本关”在流程控制区使用固定布局和互不复用的标签/确认面板；状态变化只改变后端返回的标签、启用状态、目标、影响和就地原因，不得由前端因连接或事故自行隐藏、改名或禁用。
- 起跑保护控制显示当前关“标记为已使用”或“重置为未使用”，使用绑定比赛版本、目标关和目标状态的内联确认；工作/测试模式都持久化。比赛配置关闭保护时按钮禁用。
- 比赛进入复核阶段的状态迁移完成后，归档页应立即表现为“已结束”，归档和全关成绩修订可直接执行；页面读取快照本身不得触发状态改变。
- 删除比赛在任何状态都可见且可执行，确认后必须中止当前运行再执行删除；graceful stop 失败时界面显示正在核验受管进程并可能强制结束其进程树，所有权核验失败则保留受管句柄、服务器租约和红色阻断并明确未删除，不能暗示已经释放运行。自动复核已经结束比赛时若停止失败，显示“比赛已结束，但 MockClient 未确认退出”并引导重试删除或安全关闭。

### 6.5 掉线与崩溃

- 第一条 Ready 前和起跑保护窗外的玩家掉线只更新在线状态及连接历史，不显示等待倒计时、不改变 Ready 计划也不阻断自动化。
- 从第一条 Ready 到权威 Go 后 15 秒为每关一次的起跑保护敏感期；首次掉线/fatal error 显示受影响玩家、证据、固定两分钟后的新 Ready 和自动处理结果。
- Go 前触发时显示流程已中止；Go 后触发时显示当前尝试与成绩已自动作废。新 Bulletin 与 T-60 Notice 都另起一行显示“本关起跑保护已被使用，后续不再延时。”。
- 同关保护已用后的敏感期掉线只作低干扰记录，不再展示可重复处理的事故或再次改期；保护窗外普通单人掉线同样记录但不遮挡全屏。
- MockClient 或服务器整体断线、定期 `list` 无服务器名单回显或名单汇总不符：仅冻结自动发令及依赖连接的普通命令，保持成绩、时限、上一份完整参与者状态和仍可取得的原始日志。页面展示且只展示一次完整自动恢复的当前步骤：软 `reconnect` 与重新认证；软重连中新 `Connected` 前的预期断开仍显示为同一次恢复；失败后有界 graceful stop；仍不退出时精确核验所有权并强制结束受管进程树；确认退出后固定冷却 20 秒；启动新进程并重新认证。任何步骤失败、15 秒内未认证健康、新进程再次退出或恢复后下一次定期 `list` 仍无有效回显都进入红色阻断，不显示为持续自动重试。健康态再次收到 `Connected` 显示重新认证，阻断态收到该行只更新证据、不自动消除阻断。连接恢复后仍保持暂停，裁判选择恢复自动化或使用现场恢复动作。

### 6.6 重赛交互

重赛确认面板必须展示：

- 当前关卡、模式、阶段；已有尝试时再展示尝试号、Go 时间和当前有效成绩。
- 当前流程阻断、事故、观察缺口和未决命令会从新周期阻断中隔离，但其原始状态、证据与审计永久保留，不表示命令已执行。
- 确认后立即进入当前关 Ready；已有尝试将作废但永久保留，尚未 Go 时不补造尝试，新 Go 会建立新尝试。
- 真实连接或权限仍不可用时，新 Ready 可能再次失败并形成新阻断。
- 下一次发令仍使用只影响同地图玩家的普通 Go，不会设置影响全服玩家的全局标志。

裁判在按钮旁核对结构化影响并确认后，页面立即显示 Ready，但不提前显示新比赛已开始。新权威 Go 回显后才显示新尝试和计时；强制重赛前已发出的迟到 Go 只保留在原始日志，不得让页面显示新尝试。

显式现场恢复也使用同一内联确认组件，但三个动作必须有独立裁判语言：

- 手动标记起跑的面板显示当前关、动作时刻起算、完整关卡时限、不会发送命令或回补结果，以及执行后仍暂停。
- 强制重置的面板显示当前关有效成绩将清除、旧证据保留、本关第一条 Ready 为动作后 60 秒。
- 强制下一关的面板显示下一关目标、当前关成绩保留且窗口立即关闭、`currentStageId` 立即切换、旧关立刻可修订和下一关第一条 Ready 为动作后 60 秒。

三个动作成功后必须等待新快照落地再关闭确认；刷新页面或服务恢复后仍显示同一尝试来源、起跑/截止、榜单清除或 T-60 边界结果。目标关、runtime 版本、计划或尝试影响变化后旧确认提交返回 409，页面显示具体失效原因并要求重新确认。

### 6.7 手动操作与确认等级

| 等级 | 示例 | 前端行为 |
| --- | --- | --- |
| 自动安全 | 计划公告、查询、刷新列表、自动 Ready、自动关闭 cheat | 仅记录和展示 |
| 自动竞赛 | 启用自动化后的正常倒计时和 Go | 不弹窗；遇阻断停止 |
| 手动重要 | 进入 Ready+发令流程、改下一轮时间、延长时限、提前结束、手动 Go | 展示影响摘要并确认 |
| 关键介入 | 重赛本关、手动标记当前关已起跑、强制重置本关、强制进入下一关、修改已结算名次 | 按钮旁展示结构化影响并确认 |
| 高风险管理 | kick、原始命令、强制结束进程 | 高级区域按钮旁确认 |

每个按钮必须使用独立确认文案，以后端 `targetStageId` 对应的人类可读关卡名直接说明本次会执行什么和产生什么后果；不得共用“确认流程控制”“确认比赛级操作”等泛化文案，也不展示内部目标串、哈希、状态版本或令牌有效期。后台绑定动作意图、目标关、runtime 版本、计划/尝试影响及输入；任一变化后旧确认提交返回 409，页面刷新快照并要求重新确认，不静默重放。确认请求仍在途时若目标、版本或禁用状态变化，前端必须推进该按钮的请求代次、解除旧 busy 并忽略旧请求迟到的成功、失败和 finally 回调，提示裁判按新状态重新点击；不得通过 React `key` 卸载组件来静默丢失响应，也不得把旧令牌重新挂回当前动作。不使用 `window.confirm`/`prompt`，也不要求自由文本操作原因。

动作因阶段不允许时必须直接显示实际阶段原因。例如已经进入倒数后，“手动发令”显示当前阶段不能重复发令，不能误报为权限、连接或未决命令阻断。

### 6.8 改期与通知

- “改期”区域共用一个日期时间输入框，分别提供“Ready 改期”和“关卡时限改期”按钮；两者互不改变另一项计划。
- Ready 可相对延后 1 分钟；当前关卡成绩窗口开放时，关卡时限可相对延长 1 分钟。
- 日期时间输入框明确标注 UTC+8；提交时必须携带 `+08:00` 语义，回显不得按浏览器隐式本地时区二次偏移。
- 页面同时预览受影响的公告和后续计划。
- 已发送公告不会被伪装成已撤回；初次规划、达到计分阈值、提前结束、改期、延后和保护性推迟都会发送新的 `关卡名 将在 HH:mm 发令` Bulletin。
- 通知只提供 Bulletin（顶部状态）、Notice（下方普通通知）和 Announcement（中央重要通知）三类；高级原始命令位于玩家处置区域。

### 6.9 达到最后计分名次后的轮次衔接

- 当前轮次产生“最后计分名次”时，页面立即显示默认 3 分钟后的下一轮 Ready，并展示已发送的 Bulletin；后续完赛或 DNF 不改变该计划。
- 面向裁判的通知和状态卡不得显示单调时钟或虚拟时钟的裸毫秒值；状态卡绝对时间按 UTC+8 显示。服务器 Bulletin 只显示按 UTC+8 计算的 `HH:mm`，不得使用“下一轮”或“X 分钟后”。
- 当前轮次保持“成绩接收中”，最后计分名次之后在截止点前产生的有效完赛记录继续作为有效排名记录，即使其得分为 0。
- 已完赛玩家在下一关练习产生的 cheat、Warning、完赛或 DNF 不进入上一关成绩、排除卡片或下一 Ready 阻断；原始日志窗口仍可看到这些证据。
- 下一轮 T-60 准备边界前发生人工改期时，旧窗口随新边界继续开放，但不得超过上一轮原定关卡时限；到时限只关闭窗口，不为未完成玩家补记 DNF。边界一旦发生，后续阻断、暂停或 Ready 未发出都不重新打开旧窗口。
- 下一轮第一条 Ready 前 60 秒到达时，页面在同一快照中显示 `currentStageId` 已切到下一关、上一轮窗口已关闭且上一关成绩可修订。之后到达的上一轮完赛、DNF、Warning 和 `[CHEAT]` 完赛只在原始日志中显示，不进入成绩、排除或注意事项。
- 最后一轮没有下一轮 Ready，继续按已收到的完赛/DNF、关卡时限或人工结束结算；关卡时限只关闭窗口，不生成 DNF。

### 6.10 中断恢复与继续比赛

前端与后端断开时不清空现场，持续尝试连接固定端口。后端重新启动后，页面先进入“现场恢复”视图并展示：

- 最后持久化的比赛、轮次、尝试、Go 时间、截止时间和下一动作。
- 已记录的玩家状态、成绩、事故和命令状态。
- 后端中断期间的日志缺口、通过排行榜查询补回的数据及仍无法确认的事项。
- 发送后未确认的 Go、重赛等不确定命令。

不存在不确定事项时，可在重新连接并完成检查后继续原比赛流程；存在身份冲突或不确定命令时保持暂停并使用对应处置入口。Ready、倒计时、比赛中或尾部接收阶段的服务中断显示红色“服务中断观察缺口”，逐条展示代码、完整说明和“确认带缺口继续”；确认面板明确说明不会补造事件、原证据永久保留且之后仍需恢复自动化。任意活动阶段都保留“重赛本关”作为强制恢复入口，重赛会一次隔离所有开放缺口并立即进入当前关 Ready。大厅和普通准备期重启不得显示观察缺口。恢复操作不得创建新的比赛或清空原尝试、榜单或截止时间；测试运行同样从已持久化的裁判动作后快照恢复，并显示恢复后的关卡、改期计划、尝试、榜单和虚拟时间，不能短暂回退到初始场景或旧计划。

### 6.11 比赛中开启 cheat

- 正式 Go 后、尚未获得有效完赛或 DNF 的参赛者从 cheat 关闭变为开启时，页面立即标记该选手本轮“排除”，并显示高优先级注意事项。
- 练习阶段开启 cheat 不产生处罚或事故，只更新可选状态显示。
- 已有效完赛/DNF 的选手在下一关 T-60 准备边界前开启 cheat，作为下一关练习日志忽略，不追溯改分也不形成 Ready 阻断。
- 全局 cheat off 确认后发现 cheat 开启时只发送一次 Notice 并显示黄色提醒，不阻断 Go；若到 Go 时仍开启，按本轮排除报告。
- 裁判全局开启 cheat 属于比赛事故，不能批量把所有玩家自动标为排除。

## 7. 玩家管理页面

### 7.1 在线连接

显示游戏内玩家 ID、数字连接 ID、登录时间、在线/离线、cheat、地图、区段、Ping 和最后事件。数字连接 ID 明确标注为临时现场信息。

### 7.2 比赛选手

首版无需预先选择参赛者。普通玩家出现在 login、disconnect 或 MockClient `list` 列表时，按游戏内玩家 ID 自动登记并实时显示；服务定期执行 `list` 对账。名称以 `*` 开头的连接归类为工作人员/旁观者，不自动登记。

页面提供独立的“玩家 ID → 排行榜显示名”映射，例如 `Silent_Snow → 渴望新地图`。映射可在玩家登记前后维护，只改变排行榜和导出显示，不改变成绩归属或数字连接历史。

### 7.3 状态与操作

每名选手显示：

- 游戏内玩家 ID、排行榜显示名、当前/历史数字连接 ID、在线状态和重连次数。
- 参赛、裁判、工作人员、旁观、未登记或排除角色。
- 掉线、崩溃、被踢、Warning 和人工备注。

当前玩家处置区只提供 Kick 和原始命令；显示名映射继续位于玩家页。DNF 不在玩家处置区操作，而在成绩页把对应关卡结果设置为 DNF。

### 7.4 预留界面

后续扩展报名 ID、常用名称、别名、平台账号、白名单、黑名单、禁赛记录和工作人员权限。首版仅在详情中预留字段，不提供无效按钮。

## 8. 成绩页面

### 8.1 单轮成绩

按尝试显示有效成绩、已作废尝试和未归属事件。字段至少包括名次、玩家、分数、用时、状态、DNF 原因、cheat/Warning、事件来源和修订标记。

旧尝试不能删除；默认折叠并显示作废原因。未归属记录提供关联玩家、轮次或忽略的人工处理入口。

### 8.2 总榜

默认列结构：

`变化 | 名次 | 总分 | 选手 | 轮次 1 | 轮次 2 | ...`

- 第一名单关名次使用金色 `#FFB700`。
- 第二名使用浅橙 `#FFE1B2`。
- 第三名使用浅黄 `#FFF2CC`。
- DNF 使用灰色删除线；违规结果显示“排除”并计 0 分。
- 总榜变化显示 `▲N`、`▼N` 或 `=`；上升红色、下降绿色。
- 未参加和轮次未开始显示空白或短横线，并通过悬浮提示区分。
- 显示成绩版本、最后更新时间、人工修订和待复核标记。

排行榜采用事件驱动实时更新：

- 每收到一条归属于当前有效尝试且仍在成绩接收窗口内的完赛或 DNF，立即请求并展示新的排行榜版本，不等待本轮结束。
- 即使 DNF 没有改变得分或总排名，也生成新版本并更新该玩家状态、事件序号和更新时间。
- 当前轮首个有效完赛（即当时的第一名）到达时，先锁定“应用该条完赛前”的上一轮累计排名快照，再应用本轮成绩。
- 该快照在本轮内保持不变；之后每次完赛、DNF 或人工修订都相对该快照实时计算“排名变化”。
- 排名从上一轮第 5 升至当前第 3 显示 `▲2`，从第 3 降至第 5 显示 `▼2`，未变化显示 `=`。
- 当前轮第一名出现前，“排名变化”显示 `=`；第一轮没有上一轮基线，显示 `—`。
- 截止后记录、练习记录和已作废尝试不触发有效排行榜更新。

宽表支持冻结“变化/名次/总分/选手”列并横向滚动。可快速定位玩家和轮次。

### 8.3 人工修订

成绩页负责名次与 DNF 复核：裁判直接点击对应玩家/关卡单元格，可以设置新名次或 DNF，空成绩也可以设为 DNF，空成绩也可以直接补成有名次结果。比赛运行时，只有已经越过下一关 T-60 准备边界的此前关卡可编辑；当前关和未来关保持禁用并就地说明原因。比赛结束或归档后全部关卡可编辑。得分必须根据该关发布的“名次 → 分数”配置自动重算，不提供手填单关得分或总分的入口；计分规则只能在比赛配置页修改。

保存使用按钮旁的结构化确认，不填写自由文本原因。当前实现会提供“其他玩家是否顺延”的候选项；修订名次或 DNF 时都用同一个候选项，选择顺延时确认内容要列出受影响玩家并同步重算所有受影响得分；不顺延时，直接按当前规则计分，不要求额外检查同名次或连续排名。修订采用覆盖层，不能修改原始事件。保存、快照刷新和服务重启后都必须保留排行榜完整玩家集合；撤销入口仍属后续能力。

### 8.4 复制与导出

- “复制表格”同时请求并写入 `text/html` 与 TSV `text/plain`。
- 页面、复制、CSV 和 XLSX 共用 `变化｜名次｜总分｜选手｜每关独立列` 表格模型，行列和单元格文字必须一致，不合并轮次结果。
- HTML 版本保留前三名配色、排名变化、DNF 删除线、排除样式和表格结构；纯文本使用 TSV。
- 下载入口只提供 XLSX、CSV；当前界面固定最新实时版本，后端仍可固定指定榜单版本，历史版本选择界面属于后续能力。
- 导出操作显示使用的成绩版本；导出期间成绩更新不会悄悄混入同一文件。
- 复制完成后提示兼容 Excel/腾讯在线文档；浏览器拒绝剪贴板权限时显示可选择的 TSV 手工复制区。

## 9. 日志、事件、测试运行与归档页面

### 9.1 日志与事件

原始 Client 日志不嵌入任一业务页，而以全局右下角悬浮窗提供；切换比赛时随比赛上下文刷新。窗口默认展开，可拖拽、双向缩放、手动刷新和最小化，并保持足够小的初始尺寸，避免覆盖主要流程入口；仅在更新前已位于底部时跟随新日志。工作模式展示真实 MockClient 行；测试模式的模拟玩家与模拟裁判行复用真实 `[MM-DD HH:mm:ss]` 前缀以及登录、Ready、cheat、Go、完赛和 DNF 句式。

- 原始日志与标准化事件分栏展示，默认只加载最近部分。
- 支持按玩家、轮次、尝试、类型、时间和关键字过滤。
- 标准事件可展开查看原始行、文件偏移、解析器版本和关联业务结果。
- 未识别、未归属、重复和异常编码事件有独立过滤器。
- 命令视图显示排队、发送、确认、失败、超时或不确定状态。

### 9.2 测试运行控制

- `simulation` 使用假 MockClient、虚拟时钟、模拟回显和随场景触发的故障计划。
- `static-log` 使用完整、不会再增长的 `.log`；`growing-log` 只读增量跟随增长文件。
- 普通测试场景只定义测试玩家阵容、固定随机种子和行为模型，不定义 Ready、Go、换轮或比赛结束；轮次、计分、流程策略和 1× 时间节奏与工作模式共用，裁判状态机同时服务自动和手动流程。
- 测试玩家至少提供普通玩家、游戏高手、游戏低手（超时/DNF）和捣乱分子（例如比赛中开启 cheat）行为，并在权威 Go 后自行响应当前比赛状态。
- 原速、倍速、逐事件、播放/暂停、重置和跳转 Go 属于高级静态/增长日志回放，不作为普通行为场景卡片的主流程。
- 通知文本时间只作为文本展示，不能标为真实事件时间。
- 所有结果显示“测试数据”；服务器控制不可用，模拟命令状态必须明确标为模拟。

### 9.3 测试场景与参考材料

- 普通场景库提供 20 人小型综合沙盒（8 普通、6 高手、3 低手、3 捣乱者）和 30 人大型综合沙盒（12 普通、8 高手、6 低手、4 捣乱者）；场景只声明行为，不代理裁判发令。
- 综合沙盒只带少量短暂掉线故障；Warning、DNF 和 cheat 展示为固定种子的玩家行为，不出现在故障计划中。保护期崩溃、服务器断线、MockClient 退出和时钟跳变使用独立故障场景。测试页展示阶段相对触发计划，不提供手动故障按钮或第二个自动化开关。
- 重连、Ready 掉线、cheat、重赛、命令不确定、恢复和修订继续使用最小自动化夹具，但流程事件由裁判状态机或高级回放输入产生。
- 行为场景的预期反应由人工维护，不由被测代码生成；旧三轮逐事件材料仅是高级回放/回归夹具，不出现在普通场景库。
- `2025-grandprix-sr1-13` 只作为日志格式和交错事件参考，不进入默认 CI、固定结果断言或发布门禁。
- 从历史材料发现的有效边界应先提炼为独立最小夹具，再加入正式验收。

### 9.4 归档

归档页面显示待归档内容、估算大小、目标目录、生成进度、清单和哈希校验结果。归档完成后默认只读；重新复核生成新版本，不提供覆盖原归档的操作。

## 10. 前后端接口要求

### 10.1 HTTP 资源

前端需要以下语义资源：

- 健康、版本、MockClient 进程、服务器连接和日志状态；工作运行快照包含六态连接状态、进程/连接 generation、当前裁判连接 ID、恢复步骤、恢复/冷却时间和最近服务端证据。
- 比赛草稿、发布、启用/暂停自动化、结束和归档。
- 比赛删除：草稿、运行中、已结束和已归档状态均可用，必须携带状态版本、幂等键、影响哈希和短时确认令牌；运行中的比赛先停止运行并释放服务器租约。
- 轮次、尝试、计时调整、成绩接收窗口、事故、现场恢复和重赛确认。
- 玩家连接、参赛者、身份关联、角色和备注。
- 单轮成绩、总榜、修订、撤销和导出。
- 原始/标准事件分页查询。
- 通知、流程控制、高风险管理动作，以及后端分别授权的工作连接软重连和硬重启 MockClient 动作。
- 测试运行创建、播放、暂停、调速、逐事件、跳转、重置和场景故障计划查询。

URL 与数据结构以后端文档为准，前端不得依赖 MockClient 的原始命令文本作为业务 API。

### 10.2 WebSocket 事件

至少订阅：

- 进程、六态连接、generation、裁判连接 ID、恢复步骤、权限和日志健康状态。
- 新原始日志、标准化事件和命令状态。
- 比赛状态版本、计时和下一动作。
- 玩家状态和身份冲突。
- 单轮结果、总榜版本和修订。
- 阻断、事故和需要裁判决定的事项。

WebSocket 触发的合并刷新和写操作后的主动刷新可能并发。除业务状态版本外，前端还必须给快照请求分配单调请求序号，只允许最后发出的请求更新页面；即使两份快照版本相同，旧在途响应也不得把新建测试运行、成绩或确认上下文回滚掉。

### 10.3 写动作一致性

所有写动作携带比赛 ID、期望状态版本和前端生成的幂等键。软重连、硬重启等生命周期动作在请求完成前重复提交相同动作和规范化输入时必须复用原幂等键，并把后端返回的同一在途结果渲染为一个操作；不得为一次双击生成两个幂等键，也不得把该键复用于不同动作或输入。后端返回幂等键冲突或版本冲突时，前端展示差异并要求用户基于最新状态重试，不自动覆盖。

关键介入先请求确认摘要和短时确认令牌，再提交最终操作。关卡动作从 `ActionAvailability.targetStageId` 读取目标，并让确认摘要绑定目标关、runtime 状态版本及计划/尝试影响；任一变化后令牌失效，409 响应触发快照刷新与重新确认。

## 11. 视觉、可用性与安全

### 11.1 视觉优先级

- 事故和阻断高于普通通知，普通聊天不得遮盖比赛控制。
- 工作模式和测试模式拥有明显不同的文字、颜色与水印标识。
- 颜色不能作为唯一含义，配合文字、图标和状态标签。
- 所有关键时间显示时区；当前轮次和尝试号保持固定可见。

### 11.2 易误操作防护

- 关键按钮写明动作和目标，不使用孤立的“确定”。
- 键盘快捷键不能直接触发关键介入。
- 手动 Go 与正常自动 Go 使用不同的操作入口和审计来源。
- 原始命令默认关闭并置于高级区域。
- 比赛进行中浏览器关闭或刷新不改变后端状态。

### 11.3 浏览器与本地安全

- 支持当前稳定版 Edge 和 Chrome。
- 页面只连接 `http://127.0.0.1:38623`，携带后端启动时签发的会话令牌。
- 玩家名、聊天和日志文本按不可信数据转义，禁止 HTML 注入。
- UUID、会话令牌和本地敏感路径不出现在普通成绩导出或页面截图摘要中。

### 11.4 性能

- 完整日志行进入后，关键状态应在 1 秒内反映到页面。
- 30 名玩家、30 个轮次、持续 8 小时比赛时保持可操作。
- 长日志和宽表使用虚拟化，筛选不能阻塞控制和计时展示。
- 浏览器标签页在后台时，恢复前台后立即以权威快照校准。

## 12. 前端验收标准

### 12.1 配置

- 可经内联确认整体建立 SR1–13 或 HS1–13，并显示 SR13、HS12/13 的 15 分钟默认限时。
- 可增删、复制并通过最左侧三横杠手柄排序，拖动中显示完整卡片浮层和等高目标占位；可以混排官图 SR/HS 与自制图 SR/HS，官图只配置关卡号，自制图配置名称和 32 位 MD5，逐关配置时限和计分，操作按钮不得遮挡单关计分。
- 工作模式完全不渲染测试标签、场景卡片或测试运行按钮；测试页面只属于测试比赛。
- 可将全局计分覆盖全部关卡，并明确提示会覆盖单关自定义计分。
- 比赛类型默认小型；三个 `bmmo.win` 预设不要求端口，自定义地址可按需要配置端口。

### 12.2 控制台

- 自动化首次启动时先显示默认 3 分钟准备计划及通知记录；启动后页面不逐次确认正常 Go，但持续显示下一动作和暂停入口。
- 工作模式在健康状态下仍分别显示“软重新连接”和“重启 MockClient”；两者经绑定服务器、受管 PID、进程/连接 generation 的高风险确认执行，相同幂等键的并发提交只显示一次生命周期操作。自动恢复时连接卡按六态显示当前步骤、当前 ID 和最近证据，相关动作显示就地禁用原因；恢复失败后红色阻断与两个后端允许的人工入口保持可见。仅收到 `Connected`、认证失败、显式 `list` 未唯一确认 `*ContestConsole` 或名单批次不完整/汇总不符时不得显示健康或开放普通写动作，也不得用半批名单覆盖上一份参与者状态。
- 硬重启的 UI 必须明确提示会有界停止旧进程、所有权核验通过后可能强制关闭受管进程树、等待冷却并启动新进程；所有权不能确认时显示阻断，不得暗示已关闭外部程序。连接恢复后自动化仍保持暂停。
- 同一进程地图注册中断后不显示自动重发，改为展示硬重启步骤，只有新进程认证后才重试；地图注册进行中即使身份状态为健康也不得开放普通动作、自动化或未决命令重发。明确权限失败直接阻断。结束、删除或服务关闭的 graceful stop 失败也必须展示相同所有权核验强杀结果。
- 暂停/一般阻断不停止尚未关闭的成绩接收窗口、关卡时限、T-60 关卡边界和可用的 `list` 对账；按钮切换为“恢复自动化”。恢复时未到下一边界则保持阶段，已经错过则直接进入下一阶段且不重开旧窗口。未决关键流程命令逐条支持确认已执行或显式重发，全部处理前不得恢复。
- Go 未回显时不显示比赛已开始，也不启动权威计时。
- 第一条 Ready 前和保护窗外的玩家掉线只记录；第一条 Ready 后首次敏感期掉线显示本关起跑保护已自动使用及固定两分钟的新计划。
- Go 后保护窗口内首次掉线/fatal error 显示尝试与成绩已自动作废、证据仍保留以及下一次 Ready；不再要求裁判先确认重赛。
- 已发布比赛存在活动运行时，红色“重赛本关”始终可直接使用，包括 Go 前、事故、暂停、复核和存在未决命令时；确认清楚展示立即回到 Ready、旧证据保留、已有尝试退出有效榜和新尝试等待新 Go 创建。
- 当前 Ready 且无尝试时可手动标记起跑，成功后顶部显示动作时刻对应的实际起跑、完整截止和暂停状态；强制重置本关会清除本关有效成绩并安排 60 秒后的本关 Ready；强制进入下一关会保留成绩、立即切换当前关并开放旧关修订，且安排 60 秒后的下一关 Ready。三个入口刷新和服务恢复后保持一致。
- Ready/Go 等关卡按钮和确认面板始终展示后端目标关；尾部接收目标为已规划下一关。`pausedFrom=running` 禁止 Ready、Ready+发令与手动 Go，但开放窗口仍可提前结束；目标、runtime 版本、计划或尝试变化后旧确认以 409 失效。
- WebSocket 断开时写操作禁用，恢复后状态与后端一致。
- 后端意外中止后可展示原比赛现场并继续，未确认命令和日志缺口不会被静默处理。
- 达到最后计分名次（小型 12、大型 15）时安排并通知默认 3 分钟后的下一轮，不等待本关剩余时限；下一关 T-60 准备边界前的第 13 名及以后等零分名次继续进入 API、实时快照和页面排行榜，但不改变既定计划。边界快照中当前关切换、旧窗口关闭和上一关修订权限同时生效。

### 12.3 玩家与成绩

- 无预登记名单时可发布和启动；login、disconnect、`list` 可自动登记普通玩家，`*` 旁观者被排除。
- 同一游戏内玩家 ID 重连后可看到多个数字连接 ID 归属于同一比赛选手。
- 修改排行榜显示名后榜单和导出使用新名称，但成绩仍归属于原游戏内玩家 ID。
- 身份冲突不会被前端静默合并。
- 正式比赛中未完赛玩家开启 cheat 会立即显示本轮排除和注意事项；练习中开启不处罚。
- 总榜列、前三名颜色、DNF 删除线和红升绿降与样例语义一致。
- 每条有效完赛或 DNF 都实时产生并展示新排行榜版本，不等待本轮结束。
- 关卡时限关闭成绩窗口但不会生成 DNF；需要判定 DNF 时由裁判在成绩页修订。
- 当前轮第一名出现时锁定上一轮累计排名，之后“排名变化”始终相对该快照实时更新。
- 人工修订可设置名次或 DNF，显示影响预览并生成结构化审计；运行时仅已经越过下一关 T-60 准备边界的此前关可改，结束/归档后全关可改，禁用单元格就地说明原因。玩家集合在刷新和重启后保持完整，人工修订后继续产生的自动成绩使用更高榜单版本。历史版本选择和撤销入口仍是后续能力。
- 复制到 Excel/腾讯在线文档保持行列、颜色和状态样式；页面、剪贴板 HTML/TSV、XLSX、CSV 的矩阵逐格一致并使用固定成绩版本。

### 12.4 测试运行与归档

- 测试模式具有明显水印，真实服务器控制不可用。
- 静态日志按完整文件读取，增长日志按字节偏移增量读取，源文件始终只读。
- 三轮主场景与单目标最小场景可重复运行并得到确定结果。
- 公告文本时间不会被显示成日志事件时间。
- 工作与测试导出/归档明确隔离，归档进度、清单和哈希结果可查看，已归档版本不可覆盖。

## 13. 前端实施顺序

1. 应用骨架、路由、后端会话、快照/WebSocket 同步和通用状态组件。
2. 比赛列表、新建向导、轮次/计分/策略配置及发布检查。
3. 玩家、日志事件、测试运行控制和只读成绩表。
4. 比赛控制台、自动化状态、阻断、事故和确认流程。
5. 人工修订、复制、导出、归档和诊断页面。
6. 性能、可访问性、长时运行和误操作测试。

## 14. 默认假设

- 正常自动起跑在自动化启用后无需逐次确认；手动 Go 和任意阶段的强制重赛需要确认。
- 后端固定地址为 `http://127.0.0.1:38623`。
- 默认裁判名为 `ContestConsole`，MockClient 始终自动以 `*ContestConsole` 旁观登录；工作模式只认可本机托管 MockClient，测试权威发令由裁判状态机生成，玩家行为场景不得定义发令。
- 比赛类型默认小型，默认服务器为不带端口的 `1.bmmo.win`。
- 赛前等待上限 5 分钟，重连稳定窗口 15 秒，固定 Ready/cheat/倒数时间轴，起跑保护窗口 15 秒。
- 最后计分名次由计分表推导（小型 12、大型 15）；达到该名次后立即按默认 3 分钟轮间休息安排下一 Ready，不等待本关剩余时限。
- 首版按游戏内玩家 ID 从上下线和定期 `list` 自动登记；数字连接 ID 不参与排行榜身份映射，冲突与黑白名单后续人工控制。
- 样例成绩表的前三名配色用于各轮名次单元格，DNF 灰色删除线，总榜变化红升绿降。
- 测试输入日志和工作模式日志均只读，页面只操作后端创建且按模式隔离的会话。

## 15. 开发澄清原则

开发过程中若发现规则语义、默认值、异常恢复、确认边界、界面行为或验收结果存在多种合理解释，必须先向用户确认，再更新需求文档和实现；不得以开发便利为由静默选择一种行为。
