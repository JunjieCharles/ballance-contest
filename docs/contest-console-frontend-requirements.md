# Ballance 比赛控制台前端需求文档

> 文档状态：需求基线草案  
> 适用平台：Windows 本机浏览器  
> 配套后端文档：[contest-console-backend-requirements.md](./contest-console-backend-requirements.md)  
> 参考规则：[rule.md](./rule.md)  
> 成绩表样例：[scoreboard.xlsx](./scoreboard.xlsx)

## 1. 文档目标与前端边界

### 1.1 产品目标

前端为 Ballance 比赛裁判提供本地网页控制台，用于比赛配置、玩家监控、自动流程观察、异常介入、实时成绩管理、回放和归档操作。

前端不直接访问 `BallanceMMOMockClient.exe`、比赛日志、SQLite 或归档文件。进程控制、日志解析、计时、比赛状态机和计分均由本机后端完成；前端通过 HTTP 和 WebSocket 展示后端的唯一权威状态并提交操作意图。

### 1.2 已确认决策

| 项目 | 决策 |
| --- | --- |
| 运行形态 | 浏览器中的本地网页 + Windows 本机服务 |
| 自动化权限 | 裁判启用自动控制后，正常规则流程可全自动，包括正常起跑 |
| 关键介入 | 手动 Go、比赛中重赛、作废尝试、修改已结算名次等操作必须确认 |
| 默认比赛 | 原版关卡 SR 1–13 |
| 默认服务器 | `1.bmmo.win:26676`；提供 `0.bmmo.win`、`1.bmmo.win`、`2.bmmo.win` 快捷选项 |
| 本场回放发令员 | `Solntse332` |

### 1.3 前端范围

- 比赛列表、新建向导、完整配置、发布和状态管理。
- 比赛控制台、自动流程状态、下一动作、计时、阻断和事故处理。
- 在线玩家、参赛名单、连接状态、身份冲突、角色和备注。
- 单轮成绩、实时总榜、人工修订、复制和导出。
- 原始日志、标准化事件和命令回执查询。
- 静态日志和增长中日志的只读回放控制。
- 归档创建、进度、校验结果和历史归档查看。

### 1.4 前端不负责

- 不在浏览器内启动进程、读写本地日志或计算权威比赛状态。
- 不根据浏览器计时器决定 Go、关卡超时或自动流程动作。
- 不直接拼接或执行 MockClient 命令。
- 不自动裁决录像申诉、代打、故意利用 bug 等人工事项。
- 不直接调用腾讯文档私有接口；使用标准剪贴板和文件导出兼容。

## 2. 用户与运行模式

### 2.1 用户角色

- **裁判/发令员**：配置比赛、启用自动化、处理异常、批准关键介入。
- **计分员**：查看和修订成绩、填写原因、导出榜单；首版可与裁判为同一人。
- **只读观察者**：后续能力，只查看状态和成绩；首版本机页面不单独实现账号系统。

### 2.2 运行模式

#### 托管直播模式

后端拥有 MockClient 子进程，页面开放完整控制能力。顶栏持续显示“直播控制中”、服务端、控制身份和连接状态。

#### 观察直播模式

后端只读跟随增长中的日志。页面展示实时状态和成绩，但所有命令按钮禁用，并说明“当前日志来源不可控制”。

#### 回放模式

页面使用区别于直播的固定顶栏颜色和“只读回放”水印。所有联网、发令、通知和管理按钮隐藏或禁用，避免把回放误认为现场。

## 3. 信息架构

### 3.1 一级页面

- **比赛列表**：新建、复制、继续、结束、归档、导入回放。
- **比赛配置**：基本信息、轮次、计分、玩家策略、流程策略、通知模板、发布检查。
- **比赛控制台**：当前轮次、自动化、计时、玩家摘要、实时排名、事故和关键事件。
- **玩家**：在线连接、参赛名单、身份关联、状态、角色和备注。
- **成绩**：单轮结果、总榜、待复核、人工修订、复制和导出。
- **日志与事件**：原始日志、标准化事件、命令回执和筛选定位。
- **回放**：打开日志、播放、暂停、调速、逐事件和跳转到 Go。
- **归档与设置**：归档包、MockClient 路径、默认服务器、版本和诊断。

### 3.2 导航状态

- 比赛进行中时，所有比赛内页面固定显示当前轮次、比赛状态、自动化状态和未处理事故数量。
- 离开控制台页面不会停止后端自动化；导航前只在存在未提交表单时提示。
- 浏览器刷新后从后端恢复完整快照，不出现“看似重新开始”的本地空状态。
- 同一浏览器打开多个控制标签页时，后打开页面默认只读；取得控制权需要明确操作。

## 4. 前端状态与数据同步

### 4.1 权威状态

- 比赛状态、计时、命令结果和成绩版本全部以后端为准。
- 前端可以做表单草稿和视觉倒计时，但不得用本地倒计时触发业务动作。
- 页面显示后端状态版本、最后事件序号和最后同步时间。
- WebSocket 断开时立即显示“数据可能已过期”，禁用写操作并自动重连。
- 重连后先获取完整快照，再从事件序号继续增量；发现序号缺口时重新获取快照。

### 4.2 动作状态

每个操作显示明确状态：待确认、排队、已发送、已回显确认、失败、超时或结果不确定。不能把按钮点击成功提示成服务器执行成功。

对 Go、`forcenextrestart`、重赛、kick、crash 等不自动重试的动作，若后端返回“不确定”，页面必须进入阻断状态并引导裁判核对现场。

### 4.3 通用反馈

- 表单错误定位到具体字段并保留其他输入。
- 后端业务冲突显示最新状态及冲突原因，不自动覆盖。
- 普通成功使用短暂提示；事故、阻断和不确定命令使用持久提示。
- 所有时间同时说明时区；回放中区分日志时间、接收时间和通知文本。

## 5. 比赛列表与新建配置

### 5.1 比赛列表

每项显示比赛名称、日期、服务器、模式摘要、当前轮次、状态、最后修改时间和归档状态。支持按状态、日期和名称筛选。

允许的操作：

- 新建比赛。
- 从已有比赛复制为新草稿，不复制运行事件和成绩。
- 继续未结束比赛。
- 打开已结束比赛复核或归档。
- 导入日志创建只读回放。

### 5.2 新建向导

按以下步骤组织，但允许返回修改：

1. 基本信息与服务器。
2. 比赛模板和轮次。
3. 计分方案。
4. 参赛者和身份策略。
5. 自动流程与异常策略。
6. 通知模板。
7. 发布检查与确认。

草稿自动保存到后端。未通过发布校验时可以退出，但不能启用自动控制。

### 5.3 基本信息表单

| 配置项 | 默认值/交互 |
| --- | --- |
| 比赛名称 | 必填，用于页面、导出和归档 |
| 比赛日期与时区 | 本机日期、`Asia/Shanghai`；可修改 |
| 裁判显示名 | `Solntse332` |
| MockClient 登录名 | `*Solntse332` |
| 服务器 | 默认 `1.bmmo.win:26676`，提供三个预设和自定义主机/端口 |
| 比赛类型 | 小型、大型、自定义；发布前必须确认 |
| 归档位置 | 展示后端解析后的路径，不允许自由输入危险相对路径 |

UUID 默认只显示是否已配置及末尾片段，避免普通页面泄露完整值。

### 5.4 轮次编辑器

- 提供 `SR 1–13`、`HS 1–13` 和空白模板。
- 轮次支持拖拽排序、复制、删除和批量设置。
- 每轮可选 SR/HS、原版关卡或自制图、限时、计划时间、积分方案和提前结束条件。
- 原版地图选择 `level 0..13`；自制图填写 32 位 MD5、关卡号 `0..13` 和显示名称。
- 默认限时为 10 分钟；SR13、HS12、HS13 自动预填 15 分钟，并允许覆盖。
- 已开始的轮次显示锁定状态，只能通过有审计的修订入口变更。

### 5.5 计分编辑器

内置小型和大型两套规则，并支持自定义逐名次积分：

- 小型：`20, 15, 12, 10, 8, 6, 5, 4, 3, 2, 1, 1, 1, 1, 1`。
- 大型：`30, 24, 21, 18, 16, 14, 12, 10, 8, 6, 5, 4, 3, 2, 1`。
- 15 名以后和 DNF 默认 0 分。

界面支持设置最后计分名次、统一尾部积分、单轮覆盖和是否允许负分；负分默认关闭。发布检查必须展示同分排序规则预览。

### 5.6 流程策略

前端允许配置并解释以下项：

- 公告提前量，默认 5 分钟。
- 单次延时上限，默认 5 分钟。
- Ready 缓冲，默认 15 秒。
- 起跑保护窗口，默认 Go 后 15 秒。
- 赛前掉线等待策略、迟到策略、群体异常阈值。
- 提前结束条件；默认不因前 15 名完赛立即结束。
- 普通通知是否允许一次重试；关键命令始终不自动重试。

每个策略旁显示其规则影响，而非只显示技术字段。

### 5.7 通知模板

支持编辑和预览赛前 Bulletin、Ready、掉线等待、延时、起跑中止、重赛、本轮结束、下一轮和比赛结束模板。

模板变量以可插入标签展示，包括比赛名、关卡、模式、计划时间、剩余时间和玩家名。预览必须以最终发送文本为准，并显示长度校验。

### 5.8 发布检查

发布前集中显示：

- 服务器、控制身份、日期和时区。
- 轮次顺序、地图、模式和限时。
- 计分方案和提前结束条件。
- 参赛名单和身份冲突。
- 自动化、掉线、重赛和迟到策略。
- 未填写或有风险的项目。

发布后配置生成版本号。对已开始比赛的规则修改必须经过修订流程。

## 6. 比赛控制台

### 6.1 主页面布局

在常见 1366×768 屏幕上无需滚动即可看到：

- MockClient、服务器、权限、版本和日志健康状态。
- 当前轮次、地图、模式、尝试号和比赛状态。
- Go 后权威计时、关卡限时、下一自动动作和倒计时。
- 在线、掉线、比赛中、完赛、DNF 和待复核人数。
- 自动化启用/暂停、通知、改期和事故入口。
- 单轮排名前列、总榜摘要和最近关键事件。

详细玩家、完整成绩和日志可在下方区域或对应页面展开。

### 6.2 自动化启用

页面提供一次性的“启用自动控制”流程，展示后端赛前检查：

- MockClient 连接、版本、权限和控制身份。
- 服务器、比赛时间和时区。
- 轮次、计分、参赛名单和通知模板。
- 身份冲突及其他阻断。

确认启用后，正常公告、Ready、关闭 cheat、倒计时和 Go 自动执行，不逐轮弹窗。页面始终显示下一动作及执行时间，并提供固定可见的暂停按钮。

### 6.3 比赛状态展示

使用明确状态而非仅用颜色：

`草稿 → 已发布 → 大厅/练习 → 准备检查 → Ready → 倒计时 → 比赛中 → 本轮结算 → 轮间准备 → 比赛复核 → 已结束 → 已归档`

事故/暂停作为可从 Ready、倒计时或比赛中进入的独立状态。状态卡说明进入时间、触发原因和允许的下一操作。

### 6.4 阻断展示

自动起跑被阻断时，页面必须列出每个原因，例如：

- MockClient/服务器断线或权限不足。
- Ready 阶段参赛者掉线。
- 玩家身份冲突或未处理延时申请。
- 关闭 cheat 未确认或仍有参赛者开启 cheat。
- 当前地图/模式不一致。
- 本机休眠恢复、日志中断或自动化暂停。

阻断项应区分“等待后端自动恢复”和“需要裁判处理”，并提供对应入口。

### 6.5 掉线与崩溃

- Go 前掉线：显示等待玩家、已等待时间、剩余上限和重连状态。
- 玩家重连：显示旧/新连接 ID 的关联结果；冲突时请求裁判处理。
- Go 后普通单人掉线：记录但不遮挡全屏，除非被升级为事故。
- 起跑保护窗口内崩溃或群体掉线：显示高优先级事故面板，列出证据、受影响玩家、当前成绩和“继续/重赛”影响。
- MockClient 或服务器整体断线：冻结写操作并明确表示成绩接收可能中断。

### 6.6 重赛交互

重赛确认面板必须展示：

- 当前关卡、模式、尝试号和 Go 时间。
- 事故事件、受影响玩家和当前有效成绩。
- 确认后旧尝试将作废但永久保留，新 Go 会建立新尝试。
- 后端将于下一次倒计时前设置 `forcenextrestart`。

裁判填写原因并二次确认后，页面转入“重赛准备”，不提前显示新比赛已开始。新权威 Go 回显后才显示新尝试和计时。

### 6.7 手动操作与确认等级

| 等级 | 示例 | 前端行为 |
| --- | --- | --- |
| 自动安全 | 计划公告、查询、刷新列表、正常 Ready、关闭 cheat | 仅记录和展示 |
| 自动竞赛 | 启用自动化后的正常倒计时和 Go | 不弹窗；遇阻断停止 |
| 手动重要 | 改下一轮时间、延长时限、提前结束、手动 Go | 展示影响摘要并确认 |
| 关键介入 | 比赛中重赛、作废/恢复尝试、修改已结算名次 | 二次确认并填写原因 |
| 高风险管理 | kick、crash、原始命令、强制结束进程 | 高级区域二次确认 |

确认内容必须包含目标比赛、关卡、模式、尝试号和预期后果。后台状态变化后，旧确认自动失效。

### 6.8 改期与通知

- 可把下一轮改为新的绝对时间或相对延迟。
- 页面同时预览受影响的公告和后续计划。
- 已发送公告不会被伪装成已撤回；改期后发送新的更正通知。
- 支持 Notice、Announcement、Bulletin 和普通消息快捷编辑，以及高级原始命令入口。

## 7. 玩家管理页面

### 7.1 在线连接

显示服务器连接 ID、原始名称、登录时间、在线/离线、cheat、地图、区段、Ping 和最后事件。连接 ID 明确标注为“本次连接临时 ID”。

### 7.2 比赛选手

首版从在线列表按玩家 ID 选择参赛者，选择后显示稳定的比赛选手行及其历史连接 ID。默认按不区分大小写的规范化名称提示重连关联，但同名、改名或冲突必须人工确认。

名称以 `*` 开头的连接默认归类为工作人员/旁观者，不自动加入参赛名单，允许裁判覆盖。

### 7.3 状态与操作

每名选手显示：

- 比赛显示名、当前/历史连接 ID、在线状态和重连次数。
- 参赛、裁判、工作人员、旁观、未登记或排除角色。
- 当前轮次状态：未到场、练习、等待、比赛中、完赛、DNF、待复核。
- 掉线、崩溃、被踢、Warning 和人工备注。

支持身份合并/拆分、标记缺席/DNF/待复核、修改显示名和备注。所有影响成绩的操作要求原因并展示后端审计结果。

### 7.4 预留界面

后续扩展报名 ID、常用名称、别名、平台账号、白名单、黑名单、禁赛记录和工作人员权限。首版仅在详情中预留字段，不提供无效按钮。

## 8. 成绩页面

### 8.1 单轮成绩

按尝试显示有效成绩、已作废尝试和未归属事件。字段至少包括名次、玩家、分数、用时、状态、DNF 原因、cheat/Warning、事件来源和修订标记。

旧尝试不能删除；默认折叠并显示作废原因。未归属记录提供关联玩家、轮次或忽略的人工处理入口。

### 8.2 总榜

默认列结构：

`变化 | 名次 | 积分 | 选手 | 轮次 1 | 轮次 2 | ...`

- 第一名单关名次使用金色 `#FFB700`。
- 第二名使用浅橙 `#FFE1B2`。
- 第三名使用浅黄 `#FFF2CC`。
- DNF 使用灰色删除线。
- 总榜变化显示 `▲N`、`▼N` 或 `=`；上升红色、下降绿色。
- 未参加和轮次未开始显示空白或短横线，并通过悬浮提示区分。
- 显示成绩版本、最后更新时间、人工修订和待复核标记。

宽表支持冻结“变化/名次/积分/选手”列并横向滚动。可快速定位玩家和轮次。

### 8.3 人工修订

允许修订选手归属、单关状态、名次、HS 分数、积分、DNF 原因和是否计入总榜。编辑面板展示原始值、当前有效值和所有历史覆盖。

保存前必须填写原因，并预览引发的重新排名及积分变化。名次重复或空洞时要求明确选择并列或自动顺延。修订采用覆盖层，可撤销，不能修改原始事件。

### 8.4 复制与导出

- “复制表格”同时请求并写入 `text/html` 与 TSV `text/plain`。
- HTML 版本保留标题、前三名配色、粗体、删除线和表格结构。
- 支持导出 XLSX、CSV、HTML；选择当前实时版、指定轮次结算版或最终复核版。
- 导出操作显示使用的成绩版本；导出期间成绩更新不会悄悄混入同一文件。
- 复制完成后提示兼容 Excel/腾讯在线文档；浏览器拒绝剪贴板权限时提供下载或手动复制回退。

## 9. 日志、事件、回放与归档页面

### 9.1 日志与事件

- 原始日志与标准化事件分栏展示，默认只加载最近部分。
- 支持按玩家、轮次、尝试、类型、时间和关键字过滤。
- 标准事件可展开查看原始行、文件偏移、解析器版本和关联业务结果。
- 未识别、未归属、重复和异常编码事件有独立过滤器。
- 命令视图显示排队、发送、确认、失败、超时或不确定状态。

### 9.2 回放控制

- 打开静态或增长中的 `.log`，显示源文件只读状态。
- 支持原速、倍速、逐事件、播放/暂停、从头重置和跳转到下一个 `Level XX - Go!`。
- 配置比赛年份、时区、发令员、轮次和计分方案。
- 通知文本中的时间只作为文本展示，界面不得把它标成真实事件时间。
- 回放模式中所有控制服务器的操作不可用，也不出现误导性的“模拟发送成功”。

### 9.3 回放基准展示

样例日志至少应能定位：

- SR1 正式 Go：`06-29 11:20:28`，前三名 `Silent_Snow`、`YLMJIU`、`Qiyigww`。
- SR2 正式 Go：`06-29 11:29:20`，前三名 `Silent_Snow`、`623`、`Qiyigww`。
- 两次正式 Go 前的同关成绩标为练习/非正式记录。
- `SR2, 20:18` 标为公告文本，不参与时间线校正。

### 9.4 归档

归档页面显示待归档内容、估算大小、目标目录、生成进度、清单和哈希校验结果。归档完成后默认只读；重新复核生成新版本，不提供覆盖原归档的操作。

## 10. 前后端接口要求

### 10.1 HTTP 资源

前端需要以下语义资源：

- 健康、版本、MockClient 进程、服务器连接和日志状态。
- 比赛草稿、发布、启用/暂停自动化、结束和归档。
- 轮次、尝试、计时调整、事故和重赛确认。
- 玩家连接、参赛者、身份关联、角色和备注。
- 单轮成绩、总榜、修订、撤销和导出。
- 原始/标准事件分页查询。
- 通知、流程控制和高风险管理动作。
- 回放打开、播放、暂停、调速、跳转和重置。

URL 与数据结构以后端文档为准，前端不得依赖 MockClient 的原始命令文本作为业务 API。

### 10.2 WebSocket 事件

至少订阅：

- 进程、连接、权限和日志健康状态。
- 新原始日志、标准化事件和命令状态。
- 比赛状态版本、计时和下一动作。
- 玩家状态和身份冲突。
- 单轮结果、总榜版本和修订。
- 阻断、事故和需要裁判决定的事项。

### 10.3 写动作一致性

所有写动作携带比赛 ID、期望状态版本和前端生成的幂等键。后端返回版本冲突时，前端展示差异并要求用户基于最新状态重试，不自动覆盖。

关键介入先请求确认摘要和短时确认令牌，再提交最终操作。目标、状态版本或影响变化后，令牌失效。

## 11. 视觉、可用性与安全

### 11.1 视觉优先级

- 事故和阻断高于普通通知，普通聊天不得遮盖比赛控制。
- 直播、观察直播和回放拥有明显不同的状态标识。
- 颜色不能作为唯一含义，配合文字、图标和状态标签。
- 所有关键时间显示时区；当前轮次和尝试号保持固定可见。

### 11.2 易误操作防护

- 关键按钮写明动作和目标，不使用孤立的“确定”。
- 键盘快捷键不能直接触发关键介入。
- 手动 Go 与正常自动 Go 使用不同的操作入口和审计来源。
- 原始命令默认关闭并置于高级区域。
- 比赛进行中浏览器关闭或刷新不改变后端状态。

### 11.3 浏览器与本地安全

- 支持当前稳定版 Edge 和 Chrome。
- 页面只连接本机回环地址，携带后端启动时签发的会话令牌。
- 玩家名、聊天和日志文本按不可信数据转义，禁止 HTML 注入。
- UUID、会话令牌和本地敏感路径不出现在普通成绩导出或页面截图摘要中。

### 11.4 性能

- 完整日志行进入后，关键状态应在 1 秒内反映到页面。
- 30 名玩家、30 个轮次、持续 8 小时比赛时保持可操作。
- 长日志和宽表使用虚拟化，筛选不能阻塞控制和计时展示。
- 浏览器标签页在后台时，恢复前台后立即以权威快照校准。

## 12. 前端验收标准

### 12.1 配置

- 可一键建立 SR 1–13，并显示 SR13 的 15 分钟默认限时。
- 可建立混合 SR/HS、原版关卡和 MD5 自制图比赛。
- 发布前发现无效 MD5、缺失积分、身份冲突等问题。
- 三个预设服务器和自定义主机/端口均可配置。

### 12.2 控制台

- 自动化启用后，页面不逐次确认正常 Go，但持续显示下一动作和暂停入口。
- Go 未回显时不显示比赛已开始，也不启动权威计时。
- Ready 阶段掉线显示自动等待和剩余上限。
- Go 后保护窗口内崩溃显示重赛建议；未确认前不改变成绩。
- 重赛确认清楚展示旧尝试保留、新尝试等待 Go 创建。
- WebSocket 断开时写操作禁用，恢复后状态与后端一致。

### 12.3 玩家与成绩

- 同一玩家重连后可看到多个连接 ID 归属于同一比赛选手。
- 身份冲突不会被前端静默合并。
- 总榜列、前三名颜色、DNF 删除线和红升绿降与样例语义一致。
- 人工修订显示影响预览、保存原因、历史和撤销入口。
- 复制到 Excel/腾讯在线文档保持行列；XLSX、CSV、HTML 使用固定成绩版本。

### 12.4 回放与归档

- 回放具有明显只读标识，所有服务器控制不可用。
- 可跳转到下一次正式 Go，并正确展示样例 SR1/SR2 基准。
- 公告文本时间不会被显示成日志事件时间。
- 归档进度、清单和哈希结果可查看，已归档版本不可覆盖。

## 13. 前端实施顺序

1. 应用骨架、路由、后端会话、快照/WebSocket 同步和通用状态组件。
2. 比赛列表、新建向导、轮次/计分/策略配置及发布检查。
3. 玩家、日志事件、回放控制和只读成绩表。
4. 比赛控制台、自动化状态、阻断、事故和确认流程。
5. 人工修订、复制、导出、归档和诊断页面。
6. 性能、可访问性、长时运行和误操作测试。

## 14. 默认假设

- 正常自动起跑在自动化启用后无需逐次确认；手动 Go 和比赛中重赛需要确认。
- 赛前等待上限 5 分钟，Ready 缓冲 15 秒，起跑保护窗口 15 秒。
- 默认不因前 15 名完赛立即结束，避免无必要地剥夺其他选手有效名次。
- 首版按在线连接 ID 选择选手，重连时使用规范化名称提示关联，冲突人工确认。
- 样例成绩表的前三名配色用于各轮名次单元格，DNF 灰色删除线，总榜变化红升绿降。
- 回放源始终只读，页面只操作后端创建的独立回放会话。
