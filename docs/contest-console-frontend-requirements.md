# Ballance 比赛控制台前端需求文档

> 文档状态：需求基线草案  
> 适用平台：Windows 本机浏览器  
> 配套后端文档：[contest-console-backend-requirements.md](./contest-console-backend-requirements.md)  
> 参考规则：[rule.md](./rule.md)  
> 成绩表样例：[scoreboard.xlsx](./scoreboard.xlsx)

## 1. 文档目标与前端边界

### 1.1 产品目标

前端为 Ballance 比赛裁判提供本地网页控制台，用于比赛配置、玩家监控、自动流程、异常介入、实时成绩管理、测试演练和归档操作。

前端不直接访问 `BallanceMMOMockClient.exe`、比赛日志、SQLite 或归档文件。进程控制、日志解析、计时、比赛状态机和计分均由本机后端完成；前端通过 HTTP 和 WebSocket 展示后端的唯一权威状态并提交操作意图。

### 1.2 已确认决策

| 项目 | 决策 |
| --- | --- |
| 运行形态 | 浏览器中的本地网页 + Windows 本机服务 |
| 后端地址 | 固定为 `http://127.0.0.1:32113` |
| 自动化权限 | 裁判启用自动控制后，正常规则流程可全自动，包括正常起跑 |
| 关键介入 | 手动 Go、比赛中重赛、作废尝试、修改已结算名次等操作必须确认 |
| 默认比赛 | 原版关卡 SR 1–13 |
| 默认比赛类型 | 小型 |
| 默认服务器 | `1.bmmo.win`；提供 `0.bmmo.win`、`1.bmmo.win`、`2.bmmo.win` 快捷选项，均不填写端口 |
| 默认裁判名 | `ContestConsole`，可配置 |
| 正式系统裁判来源 | 本机托管的 MockClient 是唯一裁判，不提供多裁判或远程交接 |
| 运行模式 | 仅工作模式和测试模式；发布后不可切换 |
| 测试安全 | 测试模式不启动真实 MockClient、不联网、不发送真实命令 |

### 1.3 前端范围

- 比赛列表、新建向导、完整配置、发布和状态管理。
- 比赛控制台、自动流程状态、下一动作、计时、阻断和事故处理。
- 在线玩家、参赛名单、连接状态、身份冲突、角色和备注。
- 单轮成绩、实时总榜、人工修订、复制和导出。
- 原始日志、标准化事件和命令回执查询。
- 测试模式的场景模拟、静态/增长日志、播放控制和场景故障计划。
- 归档创建、进度、校验结果和历史归档查看。

### 1.4 前端不负责

- 不在浏览器内启动进程、读写本地日志或计算权威比赛状态。
- 不根据浏览器计时器决定 Go、关卡超时或自动流程动作。
- 不直接拼接或执行 MockClient 命令。
- 不自动裁决录像申诉、代打、故意利用 bug 等人工事项。
- 不直接调用腾讯文档私有接口；使用标准剪贴板和文件导出兼容。
- 不提供多裁判协同或比赛中裁判交接；工作模式仅接受本机控制端发令。
- 不提供正式观察直播或独立回放模式。

## 2. 用户与运行模式

### 2.1 用户角色

- **裁判/发令员**：配置比赛、启用自动化、处理异常、批准关键介入。
- **计分员**：查看和修订成绩、导出榜单；首版可与裁判为同一人。
- **只读观察者**：后续能力，只查看状态和成绩；首版本机页面不单独实现账号系统。

### 2.2 运行模式

#### 工作模式

后端拥有真实 MockClient 子进程，页面开放与当前状态相符的完整控制能力。顶栏持续显示“工作模式”、服务端、控制身份和连接状态。工作模式没有外部日志观察入口。

#### 测试模式

测试模式统一承载假 MockClient、虚拟时钟、静态/增长日志、播放和场景故障计划。页面使用固定区别色及“测试数据”水印，禁止真实联网和命令；模拟动作必须明确显示为模拟结果，不能伪装成服务器成功。

模式在比赛创建时选择，发布后不可切换。测试配置可以复制成新的工作模式草稿，但事件、成绩、事故和测试状态不得复制。

## 3. 信息架构

### 3.1 一级页面

- **比赛列表**：新建、复制、继续、结束、归档、创建测试运行。
- **比赛配置**：基本信息、轮次、计分、玩家策略、流程策略、通知模板、发布检查。
- **比赛控制台**：当前轮次、自动化、计时、玩家摘要、实时排名、事故和关键事件。
- **玩家**：自动登记参赛者、游戏内玩家 ID、排行榜显示名映射、连接历史、状态和备注。
- **成绩**：单轮结果、总榜、待复核、人工修订、复制和导出。
- **日志与事件**：原始日志、标准化事件、命令回执和筛选定位。
- **测试控制台**：从玩家行为/故障场景创建测试运行并显式推进虚拟时钟；自动化只在比赛控制台启停，故障由场景按阶段触发；JSON 与逐事件日志回放不作为裁判界面入口。
- **归档与设置**：归档包、MockClient 路径、默认服务器、版本和诊断。

### 3.2 导航状态

- 比赛进行中时，所有比赛内页面固定显示当前轮次、比赛状态、本轮计划起跑时间、自动化状态和未处理事故数量。
- 离开控制台页面不会停止后端自动化；导航前只在存在未提交表单时提示。
- 浏览器刷新后从后端恢复完整快照，不出现“看似重新开始”的本地空状态。
- 重复点击当前已选比赛时保持现有快照并刷新数据，不得先清空为“请选择或新建比赛”。
- 同一浏览器打开多个控制标签页时，后打开页面默认只读；取得控制权需要明确操作。
- 前端始终连接固定地址 `http://127.0.0.1:32113`，不得在开发热更新时自动切换到随机端口或残留后端实例。

## 4. 前端状态与数据同步

### 4.1 权威状态

- 比赛状态、计时、命令结果和成绩版本全部以后端为准。
- 前端可以做表单草稿和视觉倒计时，但不得用本地倒计时触发业务动作。
- 页面显示后端状态版本、最后事件序号和最后同步时间。
- WebSocket 断开时立即显示“数据可能已过期”，禁用写操作并自动重连。
- 重连后先获取完整快照，再从事件序号继续增量；发现序号缺口时重新获取快照。
- 同一批自动流程产生的高频日志、动作和榜单事件必须合并刷新；不得为每条事件各发一次完整比赛列表与 snapshot 请求，合并后仍以最终权威快照为准。

### 4.2 动作状态

每个操作显示明确状态：待确认、排队、已发送、已回显确认、失败、超时或结果不确定。不能把按钮点击成功提示成服务器执行成功。

对 Go、`forcenextrestart`、重赛、Kick、原始命令等不自动重试的动作，若后端返回“不确定”，页面必须进入阻断状态并引导裁判核对现场。

### 4.3 通用反馈

- 表单错误定位到具体字段并保留其他输入。
- 后端业务冲突显示最新状态及冲突原因，不自动覆盖。
- 普通成功使用短暂提示；事故、阻断和不确定命令使用持久提示。
- 所有时间同时说明时区；测试日志中区分日志时间、接收时间和通知文本。

## 5. 比赛列表与新建配置

### 5.1 比赛列表

每项显示比赛名称、日期、服务器、模式摘要、当前轮次、状态、最后修改时间和归档状态。支持按状态、日期和名称筛选。

允许的操作：

- 新建比赛。
- 从已有比赛复制为新草稿，不复制运行事件和成绩。
- 继续未结束比赛。
- 打开已结束比赛复核或归档。
- 创建测试运行并选择模拟场景、静态日志或增长日志输入。

### 5.2 新建向导

新建表单默认选择工作模式；测试模式是裁判演练时主动选择的备选项。模式在创建后不可切换。

按以下步骤组织，但允许返回修改：

1. 基本信息与服务器。
2. 比赛模板和轮次。
3. 计分方案。
4. 参赛者和身份策略。
5. 自动流程与异常策略。
6. 通知模板。
7. 发布检查与确认。

草稿自动保存到后端。未通过发布校验时可以退出，但不能启用自动控制。

### 5.3 基本信息表单

| 配置项 | 默认值/交互 |
| --- | --- |
| 比赛名称 | 必填，用于页面、导出和归档 |
| 比赛日期与时区 | 本机日期、`Asia/Shanghai`；可修改 |
| 裁判名 | `ContestConsole`，可修改；界面不单独提供 MockClient 登录名，后端始终强制以 `*裁判名` 旁观登录 |
| 服务器 | 默认 `1.bmmo.win`；三个 `bmmo.win` 预设均不显示或要求端口，自定义地址可按需要包含端口 |
| 比赛类型 | 默认小型，也可选择大型、自定义 |
| 归档位置 | 展示后端解析后的路径，不允许自由输入危险相对路径 |

UUID 默认只显示是否已配置及末尾片段，避免普通页面泄露完整值。

### 5.4 轮次编辑器

- 提供 `SR 1–13`、`HS 1–13` 整体替换预设和保留当前列表的自定义模式；替换前使用按钮旁的确认面板。
- 轮次支持新增、复制、删除和上移/下移排序。
- 每轮可选 SR/HS、关卡号 `0..13`、显示名称、限时和独立计分方案。
- 默认限时为 10 分钟；SR13、HS12、HS13 自动预填 15 分钟，并允许覆盖。
- 达到“最后计分名次”时立即按默认轮间休息安排下一轮 Ready；该名次由计分表最后一个非零得分自动推导。计划不等待本关剩余时限，本轮成绩接收直到下一 Ready 实际开始或原时限先到时关闭。
- 已开始的轮次显示锁定状态，只能通过有审计的修订入口变更。

### 5.5 计分编辑器

内置小型和大型两套规则，并支持自定义逐名次计分：

- 小型：`20, 15, 12, 10, 8, 6, 5, 4, 3, 2, 1, 1`，第 13 名起为 0 分。
- 大型：`30, 24, 21, 18, 16, 14, 12, 10, 8, 6, 5, 4, 3, 2, 1`。
- “最后计分名次”由计分表最后一个非零得分自动推导；小型为 12、大型为 15，该名次之后、DNF 和排除结果默认 0 分。

当前界面支持小型、大型和自定义逐名次计分；每关可独立编辑，“应用计分方案到全部关卡”会明确提示覆盖各关自定义计分。最后计分名次只读展示并随计分表自适应。统一尾部得分和负分开关尚未提供可视化入口；负分默认关闭。

### 5.6 流程策略

前端允许配置并解释以下项：

- 公告提前量，默认 5 分钟。
- 单次延时上限，默认 5 分钟。
- 延时中的掉线玩家重连后需连续稳定在线 15 秒；全部相关玩家稳定且无其他阻断时可提前结束延时。
- Ready 缓冲，默认 15 秒。
- 起跑保护窗口，默认 Go 后 15 秒。
- 赛前掉线等待策略、迟到策略、群体异常阈值。
- 达到最后计分名次后的下一轮安排：立即按默认 3 分钟轮间休息计划，不等待本关剩余时限；下一轮实际进入 Ready 前继续接收上一轮有效成绩。
- 上一轮成绩接收截止点为“下一轮实际进入 Ready”和“上一轮关卡时限”两者中更早者；截止后的记录保留在日志中但不计分。
- 普通通知是否允许一次重试；关键命令始终不自动重试。

每个策略旁显示其规则影响，而非只显示技术字段。

### 5.7 通知模板

支持编辑和预览赛前 Bulletin、Ready、掉线等待、延时、起跑中止、重赛、本轮结束、下一轮和比赛结束模板。

模板变量以可插入标签展示，包括比赛名、关卡、模式、计划时间、剩余时间和玩家名。预览必须以最终发送文本为准，并显示长度校验。

### 5.8 发布检查

发布前集中显示：

- 服务器、控制身份、日期和时区。
- 轮次顺序、地图、模式和限时。
- 计分方案和提前结束条件。
- 最后计分名次、达到该名次后的轮间休息及上一轮成绩接收截止策略。
- 显示名映射冲突；参赛者允许为空并在运行时自动登记。
- 自动化、掉线、重赛和迟到策略。
- 未填写或有风险的项目。

检查未通过时必须在发布按钮附近逐项显示可执行的问题说明；后端返回的校验明细不得折叠成单一“发布检查未通过”。

发布后配置生成版本号。对已开始比赛的规则修改必须经过修订流程。

## 6. 比赛控制台

### 6.1 主页面布局

在常见 1366×768 屏幕上无需滚动即可看到：

- MockClient、服务器、权限、版本和日志健康状态。
- 当前轮次、地图、模式、尝试号和比赛状态。
- 本轮计划起跑时间；统一标注并按 UTC+8 显示，不用顶部状态位重复显示榜单版本。
- Go 后权威计时、关卡限时、下一自动动作和倒计时。
- 在线、掉线、比赛中、完赛、DNF 和待复核人数。
- 自动化启用/暂停、通知、改期和事故入口。
- 单轮排名前列、总榜摘要和最近关键事件。

详细玩家、完整成绩和日志可在下方区域或对应页面展开。

### 6.2 自动化启用

页面提供一次性的“启用自动控制”流程，展示后端赛前检查：

- MockClient 连接、版本、权限和控制身份。
- 服务器、比赛时间和时区。
- 轮次、计分和通知模板；参赛者不要求预登记。
- 身份冲突及其他阻断。

确认启用后，正常公告、三次 Ready、`READY!`、关闭 cheat、倒计时和 Go 自动执行，不逐轮弹窗。三次 Ready 位于起点第 0/3/6 秒；Ready 起点满 15 秒且前序命令确认后才进入真实 `3/2/1/Go`。工作和测试模式默认都按 1× 真实时间持续调度同一状态机；测试模式不能自动跳过缓冲、轮间等待或关卡时限，且只有 Go 创建尝试。虚拟时钟快进必须是裁判明确点击的演练操作。页面始终显示下一动作、可读时间、测试虚拟时钟和固定可见的暂停按钮。

### 6.3 比赛状态展示

使用明确状态而非仅用颜色：

`草稿 → 已发布 → 大厅/练习 → 准备检查 → Ready → 倒计时 → 比赛中 → 本轮结算 → 轮间准备 → 比赛复核 → 已结束 → 已归档`

事故/暂停作为可从 Ready、倒计时或比赛中进入的独立状态。状态卡说明进入时间、触发原因和允许的下一操作。

### 6.4 阻断展示

自动起跑被阻断时，页面必须列出每个原因，例如：

- MockClient/服务器断线或权限不足。
- Ready 阶段参赛者掉线。
- 玩家身份冲突或未处理延时申请。
- 关闭 cheat 未确认或仍有参赛者开启 cheat。
- 当前地图/模式不一致。
- 本机休眠恢复、日志中断或自动化暂停。

“流程动态与注意事项”以中文卡片展示流程里程碑、下一 Ready 规划、成绩窗口、违规排除、阻断、事故和不确定命令，不直接渲染 JSON。阻断项应区分“等待后端自动恢复”和“需要裁判处理”，并提供对应入口。

后端动作矩阵是按钮可用性的唯一依据；禁用按钮就地显示原因，启用按钮的确认面板展示具体影响。至少遵循：

- Ready 只在大厅、准备、暂停或重赛准备且无阻断时可用。
- 手动 Go 只在 Ready 阶段、三次 Ready/`READY!`/cheat off 全部确认、Ready 起点满 15 秒且无阻断时可用。
- Ready 延后/改期只在已有计划的赛前等待、准备、尾部接收或重赛准备阶段可用。
- 关卡时限延长/改期和提前结束只在比赛中或尾部接收且成绩窗口开放时可用。
- 重赛只在存在建议重赛的开放事故时可用；作废/恢复尝试分别要求有效/已作废目标。

### 6.5 掉线与崩溃

- Go 前掉线：显示等待玩家、已等待时间、剩余上限和重连状态。
- 玩家重连：显示旧/新连接 ID 的关联结果和连续稳定在线计时；任一相关玩家再次掉线时重新计时。
- 全部延时相关玩家连续稳定在线达到默认 15 秒，且无其他阻断时，显示“延时已提前结束”，自动重新进入准备检查和 Ready。
- Go 后普通单人掉线：记录但不遮挡全屏，除非被升级为事故。
- 起跑保护窗口内崩溃或群体掉线：显示高优先级事故面板，列出证据、受影响玩家、当前成绩和“继续/重赛”影响。
- MockClient 或服务器整体断线：冻结写操作并明确表示成绩接收可能中断。

### 6.6 重赛交互

重赛确认面板必须展示：

- 当前关卡、模式、尝试号和 Go 时间。
- 事故事件、受影响玩家和当前有效成绩。
- 确认后旧尝试将作废但永久保留，新 Go 会建立新尝试。
- 后端将于下一次倒计时前设置 `forcenextrestart`。

裁判在按钮旁核对结构化影响并确认后，页面转入“重赛准备”，不提前显示新比赛已开始。新权威 Go 回显后才显示新尝试和计时。

### 6.7 手动操作与确认等级

| 等级 | 示例 | 前端行为 |
| --- | --- | --- |
| 自动安全 | 计划公告、查询、刷新列表、正常 Ready、关闭 cheat | 仅记录和展示 |
| 自动竞赛 | 启用自动化后的正常倒计时和 Go | 不弹窗；遇阻断停止 |
| 手动重要 | 改下一轮时间、延长时限、提前结束、手动 Go | 展示影响摘要并确认 |
| 关键介入 | 比赛中重赛、作废/恢复尝试、修改已结算名次 | 按钮旁展示结构化影响并确认 |
| 高风险管理 | kick、原始命令、强制结束进程 | 高级区域按钮旁确认 |

确认内容必须包含目标、当前阶段、状态版本、预期后果和令牌有效期。后台状态变化后，旧确认自动失效；不使用 `window.confirm`/`prompt`，也不要求自由文本操作原因。

### 6.8 改期与通知

- “改期”区域共用一个日期时间输入框，分别提供“Ready 改期”和“关卡时限改期”按钮；两者互不改变另一项计划。
- Ready 可相对延后 1 分钟；当前关卡成绩窗口开放时，关卡时限可相对延长 1 分钟。
- 日期时间输入框明确标注 UTC+8；提交时必须携带 `+08:00` 语义，回显不得按浏览器隐式本地时区二次偏移。
- 页面同时预览受影响的公告和后续计划。
- 已发送公告不会被伪装成已撤回；改期后发送新的更正通知。
- 通知只提供 Bulletin（顶部状态）、Notice（下方普通通知）和 Announcement（中央重要通知）三类；高级原始命令位于玩家处置区域。

### 6.9 达到最后计分名次后的轮次衔接

- 当前轮次产生“最后计分名次”时，页面立即显示默认 3 分钟后的下一轮 Ready，并展示已发送的 Bulletin；后续完赛或 DNF 不改变该计划。
- 面向裁判的通知和状态卡不得显示单调时钟或虚拟时钟的裸毫秒值；绝对时间按 UTC+8 显示，相对计划使用“3 分钟后”等可读文案。
- 当前轮次保持“成绩接收中”，最后计分名次之后在截止点前产生的有效完赛记录继续作为有效排名记录，即使其得分为 0。
- 已完赛玩家在下一关练习产生的 cheat、Warning、完赛或 DNF 不进入上一关成绩、排除卡片或下一 Ready 阻断；原始日志窗口仍可看到这些证据。
- 下一轮因掉线、人工延时或其他阻断未实际进入 Ready 时，上一轮接收窗口继续开放，但不得超过上一轮原定关卡时限。
- 下一轮实际进入 Ready 时，上一轮接收窗口关闭。之后到达的上一轮完赛只显示为“截止后记录”，不进入成绩。
- 最后一轮没有下一轮 Ready，继续按全员完赛/DNF、关卡时限或人工结束结算。

### 6.10 中断恢复与继续比赛

前端与后端断开时不清空现场，持续尝试连接固定端口。后端重新启动后，页面先进入“现场恢复”视图并展示：

- 最后持久化的比赛、轮次、尝试、Go 时间、截止时间和下一动作。
- 已记录的玩家状态、成绩、事故和命令状态。
- 后端中断期间的日志缺口、通过排行榜查询补回的数据及仍无法确认的事项。
- 发送后未确认的 Go、重赛等不确定命令。

不存在不确定事项时，可在重新连接并完成检查后继续原比赛流程；存在日志缺口、身份冲突或不确定命令时保持暂停，由裁判确认恢复方案。恢复操作不得创建新的比赛或清空原尝试。

### 6.11 比赛中开启 cheat

- 正式 Go 后、尚未获得有效完赛或 DNF 的参赛者从 cheat 关闭变为开启时，页面立即标记该选手本轮“排除”，并显示高优先级注意事项。
- 练习阶段开启 cheat 不产生处罚或事故，只更新可选状态显示。
- 已有效完赛/DNF 的选手在下一 Ready 前开启 cheat，作为下一关练习日志忽略，不追溯改分也不形成 Ready 阻断。
- Ready 阶段发现 cheat 开启时阻断 Go 并提示关闭；若到 Go 时仍开启，按本轮排除报告。
- 裁判全局开启 cheat 属于比赛事故，不能批量把所有玩家自动标为排除。

## 7. 玩家管理页面

### 7.1 在线连接

显示游戏内玩家 ID、数字连接 ID、登录时间、在线/离线、cheat、地图、区段、Ping 和最后事件。数字连接 ID 明确标注为临时现场信息。

### 7.2 比赛选手

首版无需预先选择参赛者。普通玩家出现在 login、disconnect 或 MockClient `list` 列表时，按游戏内玩家 ID 自动登记并实时显示；服务定期执行 `list` 对账。名称以 `*` 开头的连接归类为工作人员/旁观者，不自动登记。

页面提供独立的“玩家 ID → 排行榜显示名”映射，例如 `Silent_Snow → 渴望新地图`。映射可在玩家登记前后维护，只改变排行榜和导出显示，不改变成绩归属或数字连接历史。

### 7.3 状态与操作

每名选手显示：

- 游戏内玩家 ID、排行榜显示名、当前/历史数字连接 ID、在线状态和重连次数。
- 参赛、裁判、工作人员、旁观、未登记或排除角色。
- 当前轮次状态：未到场、练习、等待、比赛中、完赛、DNF、待复核。
- 掉线、崩溃、被踢、Warning 和人工备注。

当前玩家处置区只提供 Kick 和原始命令；显示名映射继续位于玩家页。DNF 不在玩家处置区操作，而在成绩页把对应关卡结果设置为 DNF。

### 7.4 预留界面

后续扩展报名 ID、常用名称、别名、平台账号、白名单、黑名单、禁赛记录和工作人员权限。首版仅在详情中预留字段，不提供无效按钮。

## 8. 成绩页面

### 8.1 单轮成绩

按尝试显示有效成绩、已作废尝试和未归属事件。字段至少包括名次、玩家、分数、用时、状态、DNF 原因、cheat/Warning、事件来源和修订标记。

旧尝试不能删除；默认折叠并显示作废原因。未归属记录提供关联玩家、轮次或忽略的人工处理入口。

### 8.2 总榜

默认列结构：

`变化 | 名次 | 总分 | 选手 | 轮次 1 | 轮次 2 | ...`

- 第一名单关名次使用金色 `#FFB700`。
- 第二名使用浅橙 `#FFE1B2`。
- 第三名使用浅黄 `#FFF2CC`。
- DNF 使用灰色删除线；违规结果显示“排除”并计 0 分。
- 总榜变化显示 `▲N`、`▼N` 或 `=`；上升红色、下降绿色。
- 未参加和轮次未开始显示空白或短横线，并通过悬浮提示区分。
- 显示成绩版本、最后更新时间、人工修订和待复核标记。

排行榜采用事件驱动实时更新：

- 每收到一条归属于当前有效尝试且仍在成绩接收窗口内的完赛或 DNF，立即请求并展示新的排行榜版本，不等待本轮结束。
- 即使 DNF 没有改变得分或总排名，也生成新版本并更新该玩家状态、事件序号和更新时间。
- 当前轮首个有效完赛（即当时的第一名）到达时，先锁定“应用该条完赛前”的上一轮累计排名快照，再应用本轮成绩。
- 该快照在本轮内保持不变；之后每次完赛、DNF 或人工修订都相对该快照实时计算“排名变化”。
- 排名从上一轮第 5 升至当前第 3 显示 `▲2`，从第 3 降至第 5 显示 `▼2`，未变化显示 `=`。
- 当前轮第一名出现前，“排名变化”显示 `=`；第一轮没有上一轮基线，显示 `—`。
- 截止后记录、练习记录和已作废尝试不触发有效排行榜更新。

宽表支持冻结“变化/名次/总分/选手”列并横向滚动。可快速定位玩家和轮次。

### 8.3 人工修订

成绩页负责名次与 DNF 复核：裁判直接点击对应玩家/关卡单元格，可以设置新名次或 DNF，空成绩也可以设为 DNF，空成绩也可以直接补成有名次结果。得分必须根据该关发布的“名次 → 分数”配置自动重算，不提供手填单关得分或总分的入口；计分规则只能在比赛配置页修改。

保存使用按钮旁的结构化确认，不填写自由文本原因。当前实现会提供“其他玩家是否顺延”的候选项；选择顺延时，确认内容要列出受影响玩家并同步重算所有受影响得分；不顺延时，直接按当前规则计分，不要求额外检查同名次或连续排名。修订采用覆盖层，不能修改原始事件。保存、快照刷新和服务重启后都必须保留排行榜完整玩家集合；撤销入口仍属后续能力。

### 8.4 复制与导出

- “复制表格”同时请求并写入 `text/html` 与 TSV `text/plain`。
- HTML 版本保留标题、前三名配色、粗体、删除线和表格结构。
- 支持导出 XLSX、CSV、HTML；选择当前实时版、指定轮次结算版或最终复核版。
- 导出操作显示使用的成绩版本；导出期间成绩更新不会悄悄混入同一文件。
- 复制完成后提示兼容 Excel/腾讯在线文档；浏览器拒绝剪贴板权限时提供下载或手动复制回退。

## 9. 日志、事件、测试运行与归档页面

### 9.1 日志与事件

原始 Client 日志不嵌入任一业务页，而以全局右下角悬浮窗提供；切换比赛时随比赛上下文刷新。窗口默认展开，可拖拽、双向缩放、手动刷新和最小化，并保持足够小的初始尺寸，避免覆盖主要流程入口。工作模式展示真实 MockClient 行；测试模式的模拟玩家与模拟裁判行复用真实 `[MM-DD HH:mm:ss]` 前缀以及登录、Ready、cheat、Go、完赛和 DNF 句式。

- 原始日志与标准化事件分栏展示，默认只加载最近部分。
- 支持按玩家、轮次、尝试、类型、时间和关键字过滤。
- 标准事件可展开查看原始行、文件偏移、解析器版本和关联业务结果。
- 未识别、未归属、重复和异常编码事件有独立过滤器。
- 命令视图显示排队、发送、确认、失败、超时或不确定状态。

### 9.2 测试运行控制

- `simulation` 使用假 MockClient、虚拟时钟、模拟回显和随场景触发的故障计划。
- `static-log` 使用完整、不会再增长的 `.log`；`growing-log` 只读增量跟随增长文件。
- 普通测试场景只定义测试玩家阵容、固定随机种子和行为模型，不定义 Ready、Go、换轮或比赛结束；轮次、计分、流程策略和 1× 时间节奏与工作模式共用，裁判状态机同时服务自动和手动流程。
- 测试玩家至少提供普通玩家、游戏高手、游戏低手（超时/DNF）和捣乱分子（例如比赛中开启 cheat）行为，并在权威 Go 后自行响应当前比赛状态。
- 原速、倍速、逐事件、播放/暂停、重置和跳转 Go 属于高级静态/增长日志回放，不作为普通行为场景卡片的主流程。
- 通知文本时间只作为文本展示，不能标为真实事件时间。
- 所有结果显示“测试数据”；服务器控制不可用，模拟命令状态必须明确标为模拟。

### 9.3 测试场景与参考材料

- 普通场景库提供 20 人小型综合沙盒（8 普通、6 高手、3 低手、3 捣乱者）和 30 人大型综合沙盒（12 普通、8 高手、6 低手、4 捣乱者）；场景只声明行为，不代理裁判发令。
- 综合沙盒只带少量可恢复故障；保护期崩溃、服务器断线、MockClient 退出和时钟跳变使用独立故障场景。测试页展示阶段相对触发计划，不提供手动故障按钮或第二个自动化开关。
- 重连、Ready 掉线、cheat、重赛、命令不确定、恢复和修订继续使用最小自动化夹具，但流程事件由裁判状态机或高级回放输入产生。
- 行为场景的预期反应由人工维护，不由被测代码生成；旧三轮逐事件材料仅是高级回放/回归夹具，不出现在普通场景库。
- `2025-grandprix-sr1-13` 只作为日志格式和交错事件参考，不进入默认 CI、固定结果断言或发布门禁。
- 从历史材料发现的有效边界应先提炼为独立最小夹具，再加入正式验收。

### 9.4 归档

归档页面显示待归档内容、估算大小、目标目录、生成进度、清单和哈希校验结果。归档完成后默认只读；重新复核生成新版本，不提供覆盖原归档的操作。

## 10. 前后端接口要求

### 10.1 HTTP 资源

前端需要以下语义资源：

- 健康、版本、MockClient 进程、服务器连接和日志状态。
- 比赛草稿、发布、启用/暂停自动化、结束和归档。
- 比赛删除：仅草稿、已结束或已归档状态可用，必须携带状态版本、幂等键、影响哈希和短时确认令牌。
- 轮次、尝试、计时调整、成绩接收窗口、事故、现场恢复和重赛确认。
- 玩家连接、参赛者、身份关联、角色和备注。
- 单轮成绩、总榜、修订、撤销和导出。
- 原始/标准事件分页查询。
- 通知、流程控制和高风险管理动作。
- 测试运行创建、播放、暂停、调速、逐事件、跳转、重置和场景故障计划查询。

URL 与数据结构以后端文档为准，前端不得依赖 MockClient 的原始命令文本作为业务 API。

### 10.2 WebSocket 事件

至少订阅：

- 进程、连接、权限和日志健康状态。
- 新原始日志、标准化事件和命令状态。
- 比赛状态版本、计时和下一动作。
- 玩家状态和身份冲突。
- 单轮结果、总榜版本和修订。
- 阻断、事故和需要裁判决定的事项。

WebSocket 触发的合并刷新和写操作后的主动刷新可能并发。除业务状态版本外，前端还必须给快照请求分配单调请求序号，只允许最后发出的请求更新页面；即使两份快照版本相同，旧在途响应也不得把新建测试运行、成绩或确认上下文回滚掉。

### 10.3 写动作一致性

所有写动作携带比赛 ID、期望状态版本和前端生成的幂等键。后端返回版本冲突时，前端展示差异并要求用户基于最新状态重试，不自动覆盖。

关键介入先请求确认摘要和短时确认令牌，再提交最终操作。目标、状态版本或影响变化后，令牌失效。

## 11. 视觉、可用性与安全

### 11.1 视觉优先级

- 事故和阻断高于普通通知，普通聊天不得遮盖比赛控制。
- 工作模式和测试模式拥有明显不同的文字、颜色与水印标识。
- 颜色不能作为唯一含义，配合文字、图标和状态标签。
- 所有关键时间显示时区；当前轮次和尝试号保持固定可见。

### 11.2 易误操作防护

- 关键按钮写明动作和目标，不使用孤立的“确定”。
- 键盘快捷键不能直接触发关键介入。
- 手动 Go 与正常自动 Go 使用不同的操作入口和审计来源。
- 原始命令默认关闭并置于高级区域。
- 比赛进行中浏览器关闭或刷新不改变后端状态。

### 11.3 浏览器与本地安全

- 支持当前稳定版 Edge 和 Chrome。
- 页面只连接 `http://127.0.0.1:32113`，携带后端启动时签发的会话令牌。
- 玩家名、聊天和日志文本按不可信数据转义，禁止 HTML 注入。
- UUID、会话令牌和本地敏感路径不出现在普通成绩导出或页面截图摘要中。

### 11.4 性能

- 完整日志行进入后，关键状态应在 1 秒内反映到页面。
- 30 名玩家、30 个轮次、持续 8 小时比赛时保持可操作。
- 长日志和宽表使用虚拟化，筛选不能阻塞控制和计时展示。
- 浏览器标签页在后台时，恢复前台后立即以权威快照校准。

## 12. 前端验收标准

### 12.1 配置

- 可经内联确认整体建立 SR1–13 或 HS1–13，并显示 SR13、HS12/13 的 15 分钟默认限时。
- 可增删、复制、排序并建立混合 SR/HS 关卡，逐关配置关卡号、名称、时限和计分。
- 可将全局计分覆盖全部关卡，并明确提示会覆盖单关自定义计分。
- 比赛类型默认小型；三个 `bmmo.win` 预设不要求端口，自定义地址可按需要配置端口。

### 12.2 控制台

- 自动化启用后，页面不逐次确认正常 Go，但持续显示下一动作和暂停入口。
- Go 未回显时不显示比赛已开始，也不启动权威计时。
- Ready 阶段掉线显示自动等待和剩余上限。
- 延时玩家稳定在线达到 15 秒后可提前结束延时并重新进入 Ready；再次掉线会重置稳定计时。
- Go 后保护窗口内崩溃显示重赛建议；未确认前不改变成绩。
- 重赛确认清楚展示旧尝试保留、新尝试等待 Go 创建。
- WebSocket 断开时写操作禁用，恢复后状态与后端一致。
- 后端意外中止后可展示原比赛现场并继续，未确认命令和日志缺口不会被静默处理。
- 达到最后计分名次（小型 12、大型 15）时安排并通知默认 3 分钟后的下一轮，不等待本关剩余时限；截止前后续名次记录仍可保留但不影响流程。

### 12.3 玩家与成绩

- 无预登记名单时可发布和启动；login、disconnect、`list` 可自动登记普通玩家，`*` 旁观者被排除。
- 同一游戏内玩家 ID 重连后可看到多个数字连接 ID 归属于同一比赛选手。
- 修改排行榜显示名后榜单和导出使用新名称，但成绩仍归属于原游戏内玩家 ID。
- 身份冲突不会被前端静默合并。
- 正式比赛中未完赛玩家开启 cheat 会立即显示本轮排除和注意事项；练习中开启不处罚。
- 总榜列、前三名颜色、DNF 删除线和红升绿降与样例语义一致。
- 每条有效完赛或 DNF 都实时产生并展示新排行榜版本，不等待本轮结束。
- 当前轮第一名出现时锁定上一轮累计排名，之后“排名变化”始终相对该快照实时更新。
- 人工修订可设置名次或 DNF，显示影响预览并生成结构化审计；玩家集合在刷新和重启后保持完整。历史版本选择和撤销入口仍是后续能力。
- 复制到 Excel/腾讯在线文档保持行列；XLSX、CSV、HTML 使用固定成绩版本。

### 12.4 测试运行与归档

- 测试模式具有明显水印，真实服务器控制不可用。
- 静态日志按完整文件读取，增长日志按字节偏移增量读取，源文件始终只读。
- 三轮主场景与单目标最小场景可重复运行并得到确定结果。
- 公告文本时间不会被显示成日志事件时间。
- 工作与测试导出/归档明确隔离，归档进度、清单和哈希结果可查看，已归档版本不可覆盖。

## 13. 前端实施顺序

1. 应用骨架、路由、后端会话、快照/WebSocket 同步和通用状态组件。
2. 比赛列表、新建向导、轮次/计分/策略配置及发布检查。
3. 玩家、日志事件、测试运行控制和只读成绩表。
4. 比赛控制台、自动化状态、阻断、事故和确认流程。
5. 人工修订、复制、导出、归档和诊断页面。
6. 性能、可访问性、长时运行和误操作测试。

## 14. 默认假设

- 正常自动起跑在自动化启用后无需逐次确认；手动 Go 和比赛中重赛需要确认。
- 后端固定地址为 `http://127.0.0.1:32113`。
- 默认裁判名为 `ContestConsole`，MockClient 始终自动以 `*ContestConsole` 旁观登录；工作模式只认可本机托管 MockClient，测试权威发令由裁判状态机生成，玩家行为场景不得定义发令。
- 比赛类型默认小型，默认服务器为不带端口的 `1.bmmo.win`。
- 赛前等待上限 5 分钟，重连稳定窗口 15 秒，Ready 缓冲 15 秒，起跑保护窗口 15 秒。
- 最后计分名次由计分表推导（小型 12、大型 15）；达到该名次后立即按默认 3 分钟轮间休息安排下一 Ready，不等待本关剩余时限。
- 首版按游戏内玩家 ID 从上下线和定期 `list` 自动登记；数字连接 ID 不参与排行榜身份映射，冲突与黑白名单后续人工控制。
- 样例成绩表的前三名配色用于各轮名次单元格，DNF 灰色删除线，总榜变化红升绿降。
- 测试输入日志和工作模式日志均只读，页面只操作后端创建且按模式隔离的会话。

## 15. 开发澄清原则

开发过程中若发现规则语义、默认值、异常恢复、确认边界、界面行为或验收结果存在多种合理解释，必须先向用户确认，再更新需求文档和实现；不得以开发便利为由静默选择一种行为。
